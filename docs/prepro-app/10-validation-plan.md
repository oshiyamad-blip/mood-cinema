## 1. この4週間で確かめること

段階1（日々スケの配布と確認）を作る価値があるかを、作る前に確かめる。確かめる仮説は6つで、上の3つが崩れたら段階1には進まない。

| # | 仮説 | 崩れたと判断する条件 |
|---|---|---|
| H1 | 日々スケの差し替えと再連絡が頻繁で、時間と事故の損失がある | 聞き取りで、1撮影日あたりの差し替えが平均1回未満、かつ直近1年の配布の行き違い（呼び漏れ・旧版での集合など）の実例が合計5件未満 |
| H2 | 配布先が多い（20人以上）現場が、顧客の候補として実在する | 聞き取りした現場のうち、配布先20人以上かつ差し替えあり、が3現場未満 |
| H3 | 人ごとの表示と確認の集計に、受け手も配る人も価値を感じる | 手作業の試行で、受け手の確認率が50%未満、または配る人が「LINE の既読で足りる」と答える |
| H4 | 制作会社が作品ごとに払う。価格帯は¥1万〜3万／作品 | 支払う人が特定できない、または価格の聞き取りで「高すぎる」の中央値が¥1万を下回る |
| H5 | 汎用LLM＋スプレッドシートでは、差し替えの管理と確認の回収が代わりにならない | 聞き取りで、LLM やスプレッドシートの仕組みで配布と確認まで回している現場が半数を超える |
| H6 | 拘束時間の記録に手間と予算がある（段階1の売りに加えるかの判断） | 制作担当の聞き取りで、記録の手間を訴える人が3人中1人以下 |

## 2. 誰に聞くか

合計14人を目標にする。過去の行動を聞けるよう、直近1年で撮影準備を担当した人に限る。

| 区分 | 人数 | 主に確かめる仮説 |
|---|---|---|
| 配信・TVドラマの助監督（チーフ・セカンド） | 4 | H1・H2・H3 |
| 縦型ショートドラマのプロデューサー・助監督 | 4 | H1・H2（脚本を作り込まない現場が多いか、`09` B1） |
| CM・MV の制作部・助監督 | 3 | H2・H3（撮影日は少ないが配布先が多いか） |
| 制作担当・ラインプロデューサー（買い手） | 3 | H4・H6 |

### 見つけ方（上から順に当たる）

1. **知人の紹介。**映像の仕事の知人に「直近1年で香盤表や日々スケを作った人」を1人ずつ紹介してもらう。紹介が最も承諾率が高い。
2. **現場の情報を発信している人。**note や X で助監督・制作部の仕事を書いている人に、DM で依頼する（第9章の文面A）。
3. **映像系の専門学校・大学の講師。**現役の助監督が講師をしていることが多い。学校の問い合わせ窓口から依頼する。
4. **ショートドラマの制作会社。**公式サイトの問い合わせフォームから、プロデューサーへの聞き取りを依頼する（文面B）。
5. **自主映画のコミュニティ。**映画祭のスタッフ募集や、自主制作の集まりで声をかける。

謝礼は45分で¥3,000（Amazon ギフト券など）。断られる前提で、声をかけるのは30人以上にする。

## 3. 週ごとの計画

| 週 | 作業 | 時間 |
|---|---|---|
| 1週目 準備 | 声かけ30人（文面A・B）、聞き取りの予約。聞き取り台本と記録シートの用意（第4章）。手作業の試行の道具を作る（第5章）。事前申込みのページを作る（第6章）。LINE のアプリ内ブラウザで、試行の閲覧ページと確認フォームが iOS・Android で動くかを確かめる | 12時間 |
| 2週目 聞き取りと試行の開始 | 聞き取り5人。試行に協力してくれる現場を1つ決め、撮影の1週間前から始める | 12時間 |
| 3週目 聞き取りと試行の継続 | 聞き取り5人。試行の2現場目（あれば）。LLM との比較（第5.4節） | 12時間 |
| 4週目 価格と判定 | 聞き取り4人（買い手を中心に）。制作会社への事前申込みの依頼（20社以上）。結果の集計と判定（第7章） | 12時間 |

聞き取りは1人あたり45分と記録30分で、14人で約18時間。試行は1作品あたり約8時間。比較・価格・集計に残りを充てる。

## 4. 聞き取り

### 4.1 進め方の原則

- 意見ではなく、**過去の行動**を聞く。「こういうアプリがあったら使いますか」とは聞かない。「最後に差し替えが起きた日、何をしましたか」と聞く。
- 実物を見せてもらう。直近の作品の香盤表・日々スケを、画面共有で見せてもらう（保存はしない、人名と場所は隠してもらってよい、と先に伝える）。
- 最後の5分まで、KOBAN の話はしない。

### 4.2 台本（45分）

| 時間 | 聞くこと |
|---|---|
| 0〜5分 | 自己紹介と同意（録音してよいか、守秘の約束、謝礼）。直近1年の担当作品の種類・撮影日数・スタッフとキャストの人数 |
| 5〜15分 | **直近の作品で、日々スケを最後に作り直した日のこと。**何がきっかけだったか（天候・キャスト・ロケ地・台本の改訂）。前日の何時に知り、何をして、何分かかったか。誰に、どうやって送り直したか |
| 15〜22分 | **送ったあと。**全員が新しい版を見たかを、どうやって確かめたか。確かめられなかった人はいたか。直近1年で、古い版のまま動いた人・呼び漏れ・集合場所の行き違いは何回あったか。それで何が起きたか（待ち時間、撮り直し、費用） |
| 22〜30分 | **いまの道具。**香盤表と日々スケは何で作っているか（Excel・スプレッドシート・紙・アプリ）。LINE のグループの使い方。ChatGPT などを使ったことはあるか、何に使ったか。台本や香盤表を外部のサービスに入れることへの制限はあるか |
| 30〜37分 | **お金。**撮影準備の道具やソフトの費用を、直近で誰が払ったか（自分・制作会社・作品の予算）。経費にするとき何が必要だったか（請求書・領収書・承認）。外部のサービスを使うときに会社の審査はあるか |
| 37〜40分 | **買い手向け（制作担当のみ）。**拘束時間や休日の記録をどうしているか。JAC の指針や映適の審査への対応で、手間がかかっていることはあるか |
| 40〜45分 | ここで初めて KOBAN の考え（人ごとの日々スケ・確認の集計・差分つきの再配布）を一言で説明する。**価格の4問**（第4.3節）。次の作品で試してみたいか。他に話を聞くべき人を紹介してもらえるか |

### 4.3 価格の4問

「1作品の撮影準備から撮了まで使える場合」として聞く。

1. いくらなら安すぎて、品質を疑いますか。
2. いくらなら安いと感じますか。
3. いくらなら高いけれど、検討しますか。
4. いくらなら高すぎて、検討しませんか。

4人以上の回答がそろったら、2と3の交わるあたりを価格の中心とみる。

### 4.4 記録シートの列

聞き取りのたびに、スプレッドシートに1行ずつ入れる。

| 列 | 内容 |
|---|---|
| ID・日付・区分 | 個人名は書かず、ID で管理する |
| 作品の種類・撮影日数・配布先の人数 | H2 |
| 1撮影日あたりの差し替え回数・1回の作業時間 | H1 |
| 直近1年の行き違いの件数・中身・損失 | H1 |
| 確認の取り方・取れなかった割合 | H3 |
| いまの道具・LLM の利用 | H5 |
| 払った人・経費の手続き・会社の審査 | H4 |
| 価格の4問の回答 | H4 |
| 拘束時間の記録の手間（制作担当のみ） | H6 |
| 試したいか・紹介 | 段階0の判定 |
| 印象に残った発言（原文） | 要件の見直しに使う |

## 5. 手作業での試行（コンシェルジュ）

### 5.1 ねらい

アプリを作らずに、段階1の体験を現場で試す。確かめるのは H3（人ごとの表示と確認の集計に価値があるか）と、試した現場が「次の作品でも使いたい」と言うかどうかである。本業があるので、試行は配る人が自分で回せる形にし、こちらの即時対応を前提にしない。

### 5.2 道具（1週目に作る。コードは書かない）

| 道具 | 作り方 | 役割 |
|---|---|---|
| 正本のスプレッドシート | Google スプレッドシートに「撮影日」「シーン順」「人物（名前・入り時間・出番）」「変更点」のシートを用意する。助監督が直接編集する | 日々スケの正本 |
| 人ごとの閲覧ページ | スプレッドシートの「フィルタ表示」を人物ごとに作り、そのリンクを人ごとの閲覧ページにする。先頭の行に「変更点」を表示する | 自分の入り時間と出番を先頭で見せる |
| 確認ボタン | Google フォームで「確認しました」フォームを作り、名前と版番号を事前入力したリンクを人ごとに作る。回答はスプレッドシートに自動で集まる | 確認の集計 |
| 確認の一覧 | 回答のシートに、人物一覧と照合して「確認済み／前の版のまま／未確認」を出す数式を入れる | 配る人が未確認の人を一目で見る |
| LINE の文面 | 日付・集合・場所・閲覧リンク・確認リンクを並べた文面の型を、スプレッドシートの数式で人ごとに作る | 送る手間を減らす |

フィルタ表示は見せ方を絞るだけで、閲覧者がフィルタを外せば全員分が見える。日々スケはもともと全員に配る資料なので試行では許容するが、段階1の人ごとのリンクとは性質が違う（段階1では他人の情報を出し分ける）。LINE のアプリ内ブラウザでスプレッドシートを開くと、アプリへの切り替えを求められることがあるので、1週目に iOS・Android で確かめ、つまずくならフォーム側に予定を載せる形に切り替える。

連絡先（電話番号）は扱わない。人物は名前だけにし、試行の終了後にこちらの手元のデータは消す。

### 5.3 手順

1. 撮影の1週間前に、助監督と30分で使い方を合わせる（作品の香盤表から、正本のシートへの写し方を一緒にやる）。
2. 撮影日の前日に、助監督が LINE の文面を送る（グループには共通の案内、個人には個別のリンク）。
3. 差し替えがあれば、助監督が正本を直し、「変更点」に一行書き、版番号を一つ上げて再送する。
4. こちらは毎晩10分、確認の一覧と、閲覧と確認のつまずき（開けない・押せない）を見る。
5. 撮了後に、助監督と受け手の数人に15分ずつ聞く。

### 5.4 測ること

| 指標 | 合格の目安 |
|---|---|
| 受け手の確認率（版ごと） | 50%以上（段階1の目標は80%） |
| 差し替えの再送で、影響を受けた人が新しい版を確認するまでの時間 | 前日の夜のうちに8割 |
| 助監督が感じた作業時間の増減 | 「減った」または「同じで安心が増えた」 |
| 受け手のつまずき | 開けない・押せないが全体の1割未満 |
| 次の作品でも使いたいか | 助監督が「使いたい」 |
| 払うならいくらか、誰が払うか | 第4.3節と同じ4問 |

協力してくれる現場には、試行を無料にする代わりに、撮了後の聞き取りと、次の作品で正式版を使う場合の事前申込み（第6章）の検討をお願いする。可能なら、2現場目は有料（¥10,000程度）で試し、払ってもらえるかを確かめる。

### 5.5 LLM との比較（3週目、約4時間）

段階2（台本と改訂）の優先度を決めるための補助の実験である。段階1の判定には使わない。

1. 著作権の切れた戯曲（青空文庫など）か自作の脚本を1本用意し、改訂稿を自分で作る。変更点を15か所仕込む（シーンの追加・削除・順序の入れ替え、登場人物の増減、時間帯の変更、小道具の追加など）。
2. ChatGPT か Claude のプロジェクト機能に初稿と改訂稿を入れ、Google スプレッドシートの香盤表を直す案を出させる。
3. 15か所のうち拾えた数、誤って変えた数、かかった時間を記録する。

取りこぼしが1か所以下なら、段階2の価値は「差分を出すこと」ではなく「差分を配布と確認につなげること」にあると判断し、段階2の範囲を絞る。他人の台本は使わない。

## 6. 価格と事前申込み

### 6.1 事前申込みのページ（1週目に作る）

Google フォームか簡単なページで足りる。載せるのは次のとおり。

- 何が変わるか（「最新の日々スケが、全員に届いて、確認されている」）と、画面のイメージ1枚（`06` の閲覧ページの説明でよい）。
- 価格：作品プラン¥19,800（正式版の公開時）、事前申込みの作品は初回半額。
- 申込みの項目：会社名・担当者名・役職・連絡先・想定の作品（時期・種類・撮影日数・配布先の人数）・請求書払いを希望するか。
- 「正式版の公開まで請求は発生しない」と明記する。

### 6.2 依頼（4週目）

聞き取りで知り合った人と、制作会社20社以上に、ページへの案内を送る（文面C）。あわせて、外部のサービスを使うときの社内の承認の手続き（審査の有無・必要な書類）を、2社から聞き出す。

### 6.3 数えるもの

| 指標 | 目安 |
|---|---|
| 事前申込み（請求書払い希望を含む） | 3件以上 |
| 価格の4問の回答数 | 8人以上 |
| 会社の審査の手続きが分かった会社 | 2社 |

## 7. 判定

4週目の終わりに、次の表で決める。

| 結果 | 判定 | 次にやること |
|---|---|---|
| H1〜H3 が成り立ち、試行で「次も使いたい」が1現場以上、または事前申込み3件以上 | **段階1へ進む** | 主顧客（第2章の区分のうち、配布先と差し替えが最も多かったもの）と価格を `03` に書き込み、段階1の設計に入る |
| H1・H2 は成り立つが、H3 が崩れた（確認の集計は要らない、LINE の既読で足りる） | **方向を変える** | 中心を「差し替えの速さと差分の伝達」に移し、確認の機能を軽くした段階1を検討する |
| H1 は成り立つが、H2 で主顧客の候補が絞れない | **追加で2週間** | 配布先が多かった区分に絞って、聞き取りを5人足す |
| H6 が強く成り立つ | **芯を加える** | 拘束時間の検査と記録の出力を、段階1の売りの一つにする |
| H1 が崩れた | **やめる** | 段階1は作らない。得た知見を記録して終える |

判定は、印象ではなく記録シートの数字で行う。判定の根拠になった発言と数字は、`09` の補遺として残す。

## 9. 声かけの文面

### 文面A：現場の人への DM

> はじめまして。○○と申します。撮影準備の香盤表や日々スケの扱いについて調べており、現役の方のお話を伺っています。直近1年で日々スケを作ったり配ったりされた経験について、45分ほどオンラインでお聞かせいただけないでしょうか。お礼として3,000円分のギフト券をお送りします。台本や資料をお預かりすることはなく、伺った内容は個人や作品が分からない形でのみ使います。ご都合のよい日時を教えていただけましたら幸いです。

### 文面B：制作会社の問い合わせフォーム

> 撮影準備の業務（香盤表・日々スケの作成と配布）について、現場の進め方を伺っています。プロデューサーまたは助監督の方に、45分ほどオンラインでお話を聞かせていただけないでしょうか。営業ではなく、伺った内容を製品づくりの参考にする調査です。お礼としてギフト券をお送りします。資料のご提供は不要です。

### 文面C：事前申込みの案内

> 先日はお話をありがとうございました。伺った「差し替えのたびの再連絡」と「誰が最新版を見たか分からない」をなくすための仕組みを作っています。日々スケを一人ひとりに自分の入り時間が先頭に出る形で配り、確認の状況を一覧にし、差し替えたら変更点つきで配り直せます。正式版の公開時に1作品19,800円の予定で、いま事前申込みいただいた作品は初回半額にします。申込みの時点では費用は発生しません。ご関心があれば、こちらからお申込みください。［リンク］

## 10. 守秘と個人情報

- 台本・香盤表・日々スケの実物は受け取らない。見せてもらう場合は画面共有だけにし、保存しない。
- 録音は同意を取ったうえで行い、記録シートを書き終えたら消す。
- 記録シートには個人名・作品名・ロケ地名を書かず、ID で管理する。
- 試行のスプレッドシートは協力現場のアカウントで作ってもらい、こちらは閲覧の権限だけを持つ。試行の終了後に権限を外してもらう。
- 本業の副業規定と、本業の守秘義務に触れないこと（本業の取引先に声をかけない、など）を、始める前に確かめる。
