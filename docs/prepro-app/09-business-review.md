## 1. 結論

**現場で使う端末はスマホが主役で、香盤表を組む作業は PC、iPad はスクリプターと監督の端末である。** 調べた限り、日本の現場ではほぼ全員がスマホで香盤表や日々スケを受け取って見ており、紙の割本や香盤表も手元に残っている。iPad を使うのは記録（スクリプター）と一部の監督で、香盤表を作り直すのは前夜やスタッフルームの PC である。

**「現場で一番使えるアプリ」を目指すなら、フェーズ1から iPhone のネイティブアプリが要る。** 現場で効く機能（改訂ページを撮って取り込む、写真を今のシーンに結び付ける、電波がなくても開ける、1タップで今日の予定が出る）は、iOS の Web アプリでは実現できないか、信頼できない。台本の本文を端末の外へ出さずに写真から読むには、端末内の文字認識が要り、これもネイティブが前提になる。

**ただし、事業の前提は致命的に未検証である。** 最初の顧客に置いた縦型ショートドラマの量産現場は、脚本を作り込まず、小さなチームで回している例がある。痛みの頻度・損失・予算は、一度も確かめていない。作る前に4週間の検証（第6章）を行うべきである。

## 2. 現場で分かったこと

| 発見 | 根拠（確認済みのものに◆） | 意味 |
|---|---|---|
| 香盤表・日々スケは作品の LINE グループに PDF で流すのが主流で、LINE そのものは「一瞬で連絡が出来て、基本的に漏れが無い」と評価されている | ◆元東映助監督の連載、制作進行本人の知恵袋 | **LINE は置き換える相手ではない。**不満は経路ではなく、版の管理（どれが最新か）と差し替えにある。配布は LINE に乗せる形にする |
| 紙が残る理由は速さ。「紙だとパッと書き込めるので」「タブレットだと起動するとか、何か動作を一つ挟まないといけない」。紙がゼロの現場は「ほぼない」 | ◆台本印刷会社のインタビュー | **アプリは紙より速く開かなければ使われない。**ロック画面やホーム画面から1タップで「今日の次のシーン・自分の入り」が出る必要がある。印刷も一級の出力として残す |
| 脚本は深夜に上がることが多く、翌朝から撮る | ◆同上 | 改訂の取り込みと配布は、深夜から早朝の短時間に、スマホでもできなければならない |
| 最大の難所は天候と、当日・直前の変更による差し替えと再連絡 | 元東映助監督、制作会社の解説 | 当日の差し替え（撮影順の入れ替え、雨天の代替）を、スマホで数分で回せることが中心の要求になる |
| スクリプターは iPad＋ペンで記録し、衣裳・小道具の写真を iPad に集める | スクリプターのインタビュー、海外のスクリプター | iPad の主な利用者はスクリプターで、買い手も使い手も助監督とは別 |
| ロケハンや衣裳合わせでスマホのカメラを使う。保存先は Dropbox・Google ドライブ・LINE | 制作の解説記事、MA エンジニアの記事 | 「フォルダへのアクセス」の実態は、LINE や Drive からファイルを受け取って開くこと。端末のフォルダを探す需要は薄い |
| クルーが ChatGPT などで香盤を作ったという日本語の一次投稿は見つからなかった。台本は通し番号で管理され、流出が強く警戒されている | 印刷会社、ドラマ助監督のインタビュー | AI の利用は台本の秘匿と衝突する。端末内で処理できることが条件になる |
| 制作会社が作品ごとに iPad を用意する例がある。助監督の個人の収入は低い | 監督の事例記事、知恵袋 | 支払うのは会社。個人課金の余地は小さい |
| 録音部が携帯を機内モードにするよう求めることがある | 海外の AD ガイド | オフラインで動くことは必須 |
| 最も多く、最も感情的な不満は長時間労働と睡眠不足 | 知恵袋、現場の声の note | 道具の話ではないが、拘束時間の管理には予算が付く可能性がある（第3章 B13） |

## 3. ビジネス面の指摘

重大度は 致命的／重大／軽微。

| B15 | 重大 | **創業者と市場の相性、売り先への道筋がない。**競合は現役プロデューサーを前に出し、業界は人づてで回る | 業界の内側の人を共同創業者か顧問に迎える。専門学校の講師・機材レンタル・ロケ地仲介との提携を4週間で3本試す |

| B17 | 軽微 | 作品の合間の解約と季節性。継続率ではなく「次の作品でも再購入するか」が指標になる | KPI に再購入率を足す |

## 4. 仮説「カメラとファイルにアクセスできる状態で、AI を含めてアプリを使えることが強み」の評価

**判定：方向は正しい。ただし勝ち筋は「カメラがあること」ではなく、「写真を台帳の文脈に自動で結び付け、検査を通して書き戻すこと」にある。** ChatGPT のアプリでも写真から表は作れるので、カメラそのものは差にならない。差になるのは、撮ったものが「今の撮影日・今のシーン・今の版」に勝手に整理され、香盤表や日々スケと照合されることである。

| 用途 | 需要の強さ | 使う人 | 必要な技術 |
|---|---|---|---|
| 改訂稿・差し込みページ・紙の香盤表を撮って取り込み、差分を出す | 強い（準備開始と改訂のたび） | 助監督 | 端末内の文字認識（iOS の Vision は日本語に対応、縦書きの精度は要検証）、文書スキャナ |
| つながり写真（衣裳・メイク・小道具）を、今撮っているシーンへ時刻で自動に振り分ける | 強い（毎日大量） | 衣裳・メイク・スクリプター | カメラ、日々スケとの照合 |
| ロケハン写真（位置・方位）をロケ地に入れ、日照を検査する | 中 | 制作部 | カメラ、位置情報 |
| 音声メモ「S12撮了、押し30分」を消し込みと日報に変える | 中（本番中は声を出せない） | 助監督 | 端末内の音声認識 |
| LINE・Drive から届いた台本や日々スケを「共有」で受け取って取り込む | 強い | 助監督・制作部 | 共有シートの受け口（iOS の共有拡張） |
| 端末のフォルダを探して開く | 弱い | — | — |

現在の要件とは、二か所で正面から矛盾する。一つは F2-8 で、画像だけの PDF を「貼り付けか Excel 取り込みへ誘導」していることである。最も強い用途を自ら捨てている。もう一つは、本文の平文を端末の外へ出さない原則（F10・第8章）と、クラウドの LLM で台本の写真を読むことが両立しないことである。両立させるには、文字認識を端末内で行う必要があり、これはネイティブアプリが前提になる。

リスクもある。未発表のキャストや衣裳のため、私物の端末での撮影を禁じる現場がある。写真がカメラロールに入って自動で同期されると流出する。12〜15時間の撮影では電池がもたない。電波のないロケ地ではクラウドの AI は使えない。写真はアプリ内の領域だけに保存し、端末内の処理を既定にする設計が要る。

## 5. 端末と作り方の推奨

| 役割 | 現場での主な端末 | 準備での主な端末 | KOBAN が作る画面 |
|---|---|---|---|
| チーフ助監督 | スマホ（紙の割本と併用） | PC | 準備：PC の香盤表・総スケ。現場：スマホの今日の予定・差し替え・取り込み |
| セカンド以下の助監督・制作部 | スマホ | PC・スマホ | スマホの配布・確認の回収・差し替え・ロケハン写真 |
| スクリプター・記録 | iPad＋ペン | — | フェーズ2：iPad のつながり写真と記録 |
| 監督 | iPad か紙 | iPad | フェーズ2：iPad の閲覧とショットリスト |
| キャスト・各部スタッフ | スマホのみ（アプリを入れない） | — | LINE で開く閲覧ページ |

**作り方は、フェーズ1から二本立てにすることを推奨する。**

1. **PC の Web（編集の作業場）。**香盤表・総スケ・日々スケを組み、改訂を取り込む。大きな表は PC で扱う。
2. **iPhone のネイティブアプリ（現場の相棒）。**今日の予定と自分の入りをロック画面とホーム画面のウィジェットから1タップで出す。電波がなくても開く。改訂ページや紙の香盤表を撮って端末内で読み取り、差分を出す。LINE や Drive から「共有」で台本を受け取る。差し替えをスマホで数分で回し、配布して確認を集める。Android 版は利用状況を見て続ける。
3. **閲覧ページ（アプリ不要）。**キャストと各部スタッフは LINE のリンクで開く。人ごとのリンクで、場所の詳細は必要な人だけに出す。

iPad は、スクリプターと監督の機能を作るフェーズ2で、主な端末として扱う。フェーズ1では iPad 専用の画面を作らない。

これは `03` v0.2 の「フェーズ1は Web のみ」と、`07` の P3 の採用を覆す。理由は、現場での速さとカメラと端末内処理が価値の中心に入ったこと、iOS の Web アプリにはその土台がないこと、の二つである。

## 7. 判断が要ること

1. **事業の型。**少人数で続ける事業か、投資を入れて伸ばす事業か。伸ばすなら、単価、海外、隣接分野（CM・アニメの制作進行）を最初から設計に入れる。
