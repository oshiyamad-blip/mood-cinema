## 1. 方針

### 1.1 見た目の名前：「罫線帳（けいせんちょう）」

帳面の罫と墨の文字で組み、差し色は藍の一色だけにする。v0.1 から変えない。

理由は三つある。

1. 利用者が毎日見ているのは Excel と紙の香盤表である。助監督・制作部は罫で区切られた表を長時間読み書きしているので、カードや色面で区切るより、罫と余白で区切る方が目が慣れていて疲れにくい。香盤表・総スケ・日々スケはどれも表なので、表を主役にして周りを静かにする。
2. 情報の密度が高い画面で、色は「意味」のためだけに使いたい。差し色を藍の一色に絞ると、選択・主ボタン・リンクは藍、問題があるところだけが赤・橙・青になり、警告が埋もれない。台帳の状態（変わった・根拠・確認）も色を増やさず、形と語で表す（1.3）。
3. 同じトークン名のまま地を切り替える。準備期間のライト、夜や暗い部屋のダーク、〔P2〕屋外の高対比ライトの3つを、値の差し替えだけで切り替える。v0.1 の「直射日光の下でもダークで読める」は誤りだった。日なたでは、明るい地に暗い字の方が読める。

やらないこと：グラデーションの面、左罫線だけで強調するカード、絵文字、装飾のための影、赤と緑の対で差分や合否を示すこと。影は浮いている部品（トースト・メニュー・シート）だけに付ける。

### 1.2 台帳の画面としての原則

KOBAN の画面は、表を作る道具ではなく、正本を見張る計器盤として振る舞う。助監督が知りたいのは「いまの台帳は正しいか」であり、そのために次の四つを常に見えるようにする。

1. **何が変わったか**（V2）。改訂・撮影日の組み替え・他の端末の変更は、変わった場所に印を残し、影響を受ける撮影日と人まで辿れるようにする。
2. **どこから来たか**（V3）。香盤表の印は、台本の行に裏づけがあるか、人が決めたか、裏づけを失ったかを形で見分けられる。押せば根拠（台本の該当行・入力した人・取り込んだセル）に飛べる。
3. **誰が確認したか**（V4）。配布した日々スケは、最新版を確認した人・前の版で止まっている人・未確認の人を分けて数える。
4. **消えない**（データ保全）。自動の処理が値を変えたときは、必ず元の値を見られて戻せる。破壊的な操作は確認つきで、ゴミ箱かトーストの「元に戻す」で戻せる。絞り込みで隠れているだけのものは、隠れていると常に書く。

どの状態も、次の4点をそろえて出す。一つでも欠けたら、その状態は「一目で見える」とは言わない。

| 要素 | 内容 | 例（根拠を失った印） |
|---|---|---|
| 印 | その場所に、形の違う記号を置く。色は補助で、色だけでは区別しない | 香盤セルの丸を斜線で切る |
| 語 | 凡例・詳細パネル・読み上げで同じ語を使う | 「根拠を失った」 |
| 件数 | 決まった場所（ヘッダー・下部の集計・撮影日の見出し）に数を出す | 香盤表の下部の集計「根拠を失った 3」 |
| 片付ける場所 | 件数を押すと、一覧と対処の操作がある所へ行ける | 行の絞り込み「根拠を失った印を含む行」と、詳細パネルの「行に結びつけ直す／外す」 |

見せ方の優先順位は、エラー＞警告＞注意＞来歴（変わった・根拠・確認）の順にする。来歴の印は警告の色を使わない。ただし「根拠を失った」と「再配布が必要」は対処が要るので警告の段階に入れる。

### 2.6 検算の方法

sRGB の各成分 c（0〜1）を、c ≤ 0.04045 なら c/12.92、それ以外は ((c+0.055)/1.055)^2.4 で線形化し、相対輝度 L = 0.2126R + 0.7152G + 0.0722B を求める。対比は (明るい方の L + 0.05) ÷ (暗い方の L + 0.05)。本書の値はすべてこの式を Python で計算したもので、レビューの指摘値（`--rule-strong` on `sunken` 2.97、ダークの `--rule-strong` on `accent-soft` 2.77、`--accent` on `--err` 1.22、ダークの `--rule` on `paper` 1.57）も同じ計算で再現した。新しい色を足すときは、置かれるすべての地に対して同じ計算をし、この章に書き足す。

| 束 | 中身 | 上限 | 取得の時期 |

| 数字 | BIZ UDGothic 400／700、英数字と記号 | 2ウェイト合計 100KB（`04` 14.2 は 400 だけで 100KB。集合時刻などの太字の数字に 700 が要るので、同じ上限の中で 700 も持つ） | 起動時 |

### 3.5 OS の文字サイズへの追従

v0.1 は追従を約束しながら px で組んでいた。v0.2 では rem で組んだうえで、環境ごとに次のようにする。

| 環境 | 方法 |
|---|---|
| PC のブラウザ | ブラウザの既定の文字サイズに rem が追従する。ページの拡大（Ctrl/⌘ ＋）は 200% まで、横スクロールなしで使えること |
| iOS の Safari・ホーム画面の PWA | Dynamic Type は Web に自動では効かない。起動時と画面に戻ったとき（`visibilitychange`）に、`font: -apple-system-body` を当てた見えない要素の文字サイズを読み、標準の 17px に対する比を `--os-text-scale` に入れて `html { font-size: calc(100% * var(--os-text-scale)) }` とする |
| Android の Chrome | 「テキストの拡大縮小」がページに効くことを実機で確かめる。効かない端末では、アプリの設定の「文字の大きさ」で補う |
| ストア版〔P2〕 | Capacitor の WebView は OS の設定を自動では反映しない（U13）。ネイティブから倍率（iOS の UIContentSizeCategory、Android の fontScale）を受け取り、同じ `--os-text-scale` に入れる |

- 倍率は 0.85〜2.0 に丸める。アプリの設定の「文字の大きさ」（90〜150%）は、OS の倍率にさらに掛ける。
- `-webkit-text-size-adjust: none` は使わない。
- 全画面を 100%・150%・200% で確かめる。香盤表の固定列と見出しの振る舞いは 8.5 に定める。

## 5. 表示の密度

`03` F5-2 のとおり、香盤表は PC で高密度を既定にし、タッチの端末では 44px にする（U1）。

| | 高密度（PC） | 標準（タッチ） |
|---|---|---|
| 既定になる条件 | `(pointer: fine)` かつ幅 1024px 以上 | それ以外（`(pointer: coarse)` を含む） |
| 香盤セル・表の行の高さ | 1.75rem（28px） | 2.75rem（44px） |
| 表の字 | 0.875rem、列見出し 0.8125rem | 同じ |
| 香盤の固定列 | 話・番号・柱・時間帯・屋内外・ペラ・撮影見積・撮影日 | 話・番号・柱だけ固定し、残りの属性は要素列と一緒に流す |
| 総スケのシーン片 | 2行（開始・番号・柱・時間帯・屋内外／ペラ・見積・主な出演者） | 3行（v0.1 と同じ） |
| 変えないもの | ボタン・入力欄・タブ・一覧の行（44）、字の最小（12px） | 同じ |

切り替えは香盤表のツールバーの「密度」と、設定＞表示 で行う。高密度を手で選べるのは、精密なポインタがあるとき（`(any-pointer: fine)`。トラックパッドをつないだタブレットなど）だけで、タッチだけの端末では選べない。選んだ密度は端末ごとに覚える（localStorage。読み書きは try/catch で包み、失敗したら既定に戻す）。

**高密度での見え方**（1440×900、レール 88px、詳細パネルを閉じた状態、文字100%）：

- 固定列の幅は、話 2rem・番号 2.5rem・柱 10rem・時間帯 1.75rem・屋内外 1.75rem・ペラ 2.5rem・撮影見積 2.5rem・撮影日 3rem の合計 26.75rem（428px）。単発作品は話を出さず 396px。
- 要素列は (1440 − 88 − 428 − スクロールバー 16) ÷ 28 ≒ **32列**（v0.1 は約11列）。1024幅では約17列。柱の幅を「狭い」（6rem）にすると 1440幅で約34列。`04` 13.4 の概算（固定列 約452px で約31列、1024幅で約16列）とは固定列の幅の置き方の差で、本書の幅を正とする。
- 行は 900 − アプリバー 48 − ツールバー 52 − 列見出し 約120 − 下部の集計 32 ＝ 648 ÷ 28 ≒ **23行**（v0.1 は約12行）。
- 1024幅のタッチ（横向きタブレット）では、固定が話・番号・柱（狭い）で約168px、要素と属性の列は (1024 − 88 − 168) ÷ 44 ≒ 17列。
- 390幅のスマホは標準で約5列しか見えないので、香盤表の既定の表示を「シーンの一覧」にする（9.6）。

## 6. フォーカスの輪郭

すべての地で同じ形にする。内側 2px の `--focus-inner`、外側 2px の `--focus-outer` の二重線で、どちらか一方が、置かれた地に対して必ず3:1を超える（U6）。

```css
:focus-visible {
  outline: 2px solid transparent;  /* 強制カラーモードでは、この outline がシステムの色で見える */
  outline-offset: 2px;
  box-shadow: 0 0 0 2px var(--focus-inner), 0 0 0 4px var(--focus-outer);
}
/* 切り抜かれる場所（香盤セル、スクロール容器の中の行）では内側に描く */
.k-focus-inset:focus-visible {
  box-shadow: inset 0 0 0 2px var(--focus-outer), inset 0 0 0 4px var(--focus-inner);
}
```

置かれる地ごとの対比（外側／内側）。各行の大きい方が3:1を超えていればよい。最も低いのはダークの `info-fill` の上の 6.10 である。

|---|---|---|
| `paper` | 7.41 ／ 1.10 | 8.21 ／ 1.02 |
| `surface` | 8.00 ／ 1.02 | 7.55 ／ 1.06 |
| `sunken` | 6.78 ／ 1.20 | 8.58 ／ 1.07 |
| `accent-soft` | 6.71 ／ 1.21 | 6.21 ／ 1.29 |
| `accent`（主ボタンの地） | 1.00 ／ 8.15 | 1.00 ／ 8.02 |
| `--err` の塗り（v0.1 は 1.22） | 1.22 ／ 6.69 | 1.03 ／ 8.30 |
| `warn-fill` | 6.50 ／ 1.25 | 1.27 ／ 10.22 |
| `info-fill` | 6.94 ／ 1.18 | 6.10 ／ 1.32 |

規則：

## 8. 香盤表のグリッド

`03` F5-7「キーボードで操作でき、支援技術では表として読める」と、U2（全セルが独立したタブ停止で、読み上げで状態が二重になる）への答えとして、香盤表は ARIA の grid の作法に従う。

### 8.1 構造

- 表全体は `role="grid"`、`aria-label="香盤表"`。`aria-rowcount`（見出し2行＋全シーン数）と `aria-colcount`（固定列＋全要素列）で、描いていない行・列を含む総数を伝える。
- 見出しの1行目（カテゴリ）は `role="columnheader"` に `aria-colspan`。2行目（要素名）は `role="columnheader"` で、出演シーン数は見出しの中の補足として `aria-describedby` で結ぶ。
- 各行は `role="row"` に `aria-rowindex`。詳細パネルの対象になっている行には `aria-selected="true"`。
- 番号のセルは `role="rowheader"`（中身は「S12」）。柱・時間帯などの属性は読み取りだけの `role="gridcell"`。
- 要素のセルは `role="gridcell"` の中に `<button type="button" aria-pressed="true|false">` を1つ置く。描いているセルには `aria-colindex`。

### 8.2 タブ停止とキーボード

タブ停止は表全体で1つにする（roving tabindex）。最後にいたセルの button だけを `tabindex="0"`、他はすべて `-1` にする。初めて入ったときは、最初のシーンの最初の要素セルにいる。

| キー | 動き |
|---|---|
| ← ↑ → ↓ | 1セル移動（固定列にも入れる） |
| Home ／ End | 行の先頭／末尾 |
| Ctrl/⌘＋Home ／ End | 表の最初／最後のセル |
| PageUp ／ PageDown | 見えている行数ぶん移動 |
| Space | 印の切り替え（要素セル） |
| Enter | 行の詳細パネルを開き、パネルの最初の項目へ移る。Esc で表の同じセルへ戻る |
| Shift＋F10、コンテキストメニューキー | セルのメニュー（備考、根拠を見る、台本で見る） |
| / | 列の検索欄へ移る（表にフォーカスがあるときだけ効く。1文字のショートカットだが、WCAG 2.1.4 の「その部品にフォーカスがあるときだけ有効」の条件を満たす） |
| Ctrl/⌘＋Z ／ Shift＋Ctrl/⌘＋Z | 取り消し／やり直し（作品内の編集だけ） |
| Tab | 表から出て、次の部品（詳細パネルか下部の集計）へ |

矢印で見えない位置へ移ったら、そのセルが固定列・見出しの陰に隠れないよう、`scroll-padding` の内側までスクロールする（第6章の規則2）。

### 8.3 読み上げ

- ボタンの名前は「行見出し＋列見出し」で、`aria-labelledby` で番号セルと要素の見出しを指す。例「S12 父」（話を使う作品では話のセルも指して「2話 S12 父」）。**状態の語（「印あり」）は名前に入れない。** 状態は `aria-pressed` だけで伝える（v0.1 は `aria-label="シーン2 父 印あり"` と `aria-pressed` の両方で読まれ、二重になっていた）。
- 根拠の状態は、既定（台本の行から）と違うときだけ `aria-describedby` で足す。「台本の行なし」「根拠を失った：第2稿で行が消えました」「上書きされました」「〔P2〕AIの提案、未採用」。
- 改訂で変わった行は、番号セルに見える「＊」を置き、読み上げは番号セルの `aria-describedby` で「第2稿で変更」とする。
- 印の切り替えでライブリージョンのお知らせは出さない。`aria-pressed` の変化だけで読まれる。列への移動のように、フォーカスの位置だけでは分からない結果だけを `aria-live="polite"` で伝える。
- NVDA（Chrome・Firefox）、VoiceOver（macOS の Safari、iOS の Safari）、TalkBack（Android の Chrome）で、見出しと状態がそれぞれ一度ずつ読まれることを確かめる。行・列の見出しを自動で読む読み上げソフトで見出しが二重に読まれる場合は、名前を列見出しだけにする（状態の二重は、どの読み上げソフトでも起こさない）。

### 8.4 列の絞り込み・検索・移動

ツールバーの並びは「話」「列を探す（検索欄）」「列の絞り込み」「行の絞り込み」「並び」「根拠の強調」「密度」「書き出す」。

- **根拠の強調**（`04` 13.4 のトグル）：オンにすると、台本の行から来た ● を `--ink-3`（paper 上 5.43）に下げ、○ と斜線の印だけを `--ink`・`--warn-ink` のまま残して浮かび上がらせる。形の区別（1.3）はオフでも常に出す。`aria-pressed` のトグルで、端末ごとに覚える。
- **列を探す**：`role="combobox"` の検索欄で、候補は `listbox`。人物名・役名・要素名の部分一致。Enter で、その列を固定列のすぐ右までスクロールし、フォーカスを現在の行のその列へ移す。見出しを 1.5秒だけ `accent-soft` で示す（`prefers-reduced-motion` のときは動かさず、色だけを付けて次の操作で消す）。お知らせ「父の列へ移動しました（150列中23列目）」。
- **シーンへ移動**：同じ検索欄で「S12」「12」「2話S12」を受け付け、その行へ移る。
- **列の絞り込み**：カテゴリの選択、「選んだ撮影日の出演者だけ」、「選んだ行に印のある列だけ」、「印のない列を隠す」、手で隠した列の一覧。
- **行の絞り込み**：話、撮影日、未割当、改訂で変わった、根拠を失った印を含む、台本の行なしの印を含む、上書きされた項目を含む。
- 絞り込み中は、ツールバーの下に条件のラベル（それぞれに解除の×、44×44）を並べ、「150列中32列・300シーン中41シーンを表示」と「絞り込みを解除」を出す。隠れているだけで消えていないことを常に示す。
- **列の並び**：人物の既定は出演シーン数の多い順（`05` の `personOrder: 'appearance'`）。「手動」にすると、見出しをドラッグするか、「列の並べ替え」ダイアログの「上へ」「下へ」で動かす（ドラッグだけの操作にしない）。
- **行の並び**：話→台本順・ロケ地順・撮影日順（F5-5）。

### 8.5 固定列と見出し

- 固定列（高密度では話〜撮影日、標準では話・番号・柱。第5章）は `position: sticky` で左に、見出し2行は上に固定する。固定列の右端は 2px の `rule-strong`。
- 幅と高さは rem で持ち、文字の倍率に合わせて伸びる。そのうえで、字を大きくしても固定部分が表を食い尽くさないよう、二つの上限を持つ（U13 と合わせた U1 の対策）。
  1. 固定列の合計幅が表の幅の 45% を超えたら、属性の列（時間帯〜撮影日）を固定から外して流す。それでも超えたら柱を「狭い」にし、柱の全文は行見出しのツールチップと詳細パネルで読ませる。
  2. 列見出しの高さは `min(9rem, 30vh)` を上限にし、収まらない名前は「…」で切る。CSS で切るだけなので DOM には全文があり、読み上げと検索は全文を使う。マウスを載せると全文を出す。
- 固定の上端・左端の大きさが変わったら、スクロール容器の `scroll-padding` も同じ値に更新する。

### 8.6 仮想スクロールと性能

縦横とも、見えている範囲と前後数行・数列だけを描く。フォーカスのあるセルは、見えない位置にあっても描画から外さない（外すとフォーカスが失われる）。300シーン×150列で表示2秒以内・切り替えの反映200ms以内（`03` 第8章）を、PC の中位機で測る。

### 8.7 マウスとタッチ

- クリック・タップで印を切り替える。行見出しを押すと行を選び、詳細パネルを開く。
- フォーカスとマウスが載っているセルの行見出しと列見出しの地を `accent-soft` にする（十字のハイライト）。150列の表で、どの人の列を見ているかを見失わないため。
- 長押し・右クリックでセルのメニュー。
- 範囲をなぞって一度に印を付ける操作は作らない（誤操作で大量の印が付き、気づきにくいため）。

| 並び | 最終更新の降順。9本以上で検索欄を出す |
| 主ボタン | 「新しい作品を作る」 |
| 新規作成（`/new`）1 | 題名（必須、1〜100字）、種別（映画／ショートドラマ／連続ドラマ／CM／MV／その他）、撮影期間（任意）、「話を使う」（ショートドラマ・連続ドラマでは既定オン、「最初の話数」1〜200） |
| 新規作成 2 | 同じページの下の区画「どこから始めますか」。同じ大きさの選択肢3つ（それぞれ 44 以上のボタンで、1行の説明つき）：「台本から」（テキスト・PDF・Word・貼り付け）→ 9.2、「Excel・CSV の香盤表から」（他のサービスや LLM で作った表も）→ 9.4、「空の香盤表から」→ 9.6 の空状態 |
| バックアップから戻す | 副のボタン。JSON から、常に新しい作品として作る（題名に「（復元）」を付ける） |
| 空状態（初回） | 一文「台本・Excel・空の表のどれからでも始められます」と、新規作成 2 の3つの選択肢をそのまま並べる（押すと、その始め方を選んだ状態で `/new` を開く）。この状態では主ボタンを出さない。下に文字のリンク「見本の作品を開く」（同梱の例を新しい作品として作る） |
| ログインしていない | 上部に一度だけ「ログインすると、別の端末とも同期できます」（閉じられる）。作品は「端末に保存済み」 |
| 利用の上限 | 上限は `04` 第16章の値（ログインしていない端末は進行中2本・1作品の撮影日5日、ベータでログインした利用者は進行中10本（仮）・撮影日は無制限（仮））。上限を超える作品は消さずに「保管」（閲覧と書き出しのみ）で作る・戻す。作品一覧の上に「進行中 2/2本」と、保管の作品を進行中にする操作（「進行中にする」。上限の中で、どれを進行中にするかを利用者が選ぶ）を出す |

**ゴミ箱**（`/trash`）：作品と、作品の中の項目（シーン・人物・印・撮影日など）を作品ごとにまとめて出す。各行は名前、種類、ゴミ箱へ移した日、残り日数（サーバーの時刻で数える）、「元に戻す」、「完全に削除」。「元に戻す」は権利や利用の上限に関わらず常に押せる（T15）。上限を超える作品は保管として戻し、トーストでそう伝える（`04` 8.7）。「完全に削除」は危険ボタンで、確認ダイアログで項目名の入力を求める。上に一文「30日を過ぎると自動で消えます」。空状態「ゴミ箱は空です」。

### 9.3 取り込み確認（`/p/:pid/import/:draftId/review`）

- PC は左に縦書きの原文（スクロール容器ごと `vertical-rl` にして右端から読み始める）、右に解析結果。スマホは上部の切り替え「原文／結果」。
- 上部に「要確認 N件」（警告の段階）と、種類ごとの件数ボタン（柱らしい行・話者が1回だけ・閉じない括弧・屋内外が不明・時間帯が不明）。押すと次の該当箇所へ移る。原文の該当行は警告の地を敷き、行末に［柱らしい行］などの語を添える。
- **シーン表**：番号・見出し・ロケ地（候補）・時間帯・屋内外・ペラ・話者。その場で直せる。判定できなかった値は注意の枠の空欄にし、その場で選ぶ。操作は「直前と結合」「この行で分割」「番号の振り直し（全体）」。どれもツールバーの取り消しで戻せる。
- **話者の整理**：話者ごとの出現回数の一覧。「〜にまとめる」（「タロウ」→「太郎」）、「人物にしない」（一同・声など）、区分（キャスト（既定）／エキストラ）。字幕・テロップ・音（「遠くで」など）は最初から話者にしないが、「人物にしなかった候補」として一覧の下に見せ、戻せるようにする（F2-4）。
- **ロケ地の整理**（C7）：柱の見出しから作った候補を一覧にし、同じ場所らしいもの（「太郎の家・居間」「太郎の家・玄関」）を「太郎の家」にまとめる提案を付ける。操作は「まとめる」「分ける」「ロケ地にしない」。ロケ地がまとまっていないと、総スケの移動時間の計算と、ロケ地順の並べ替えが空振りすることを一文で書く。
- **根拠**：上部に一文「確定すると、作った印はすべて『準備稿の何行目か』を根拠に持ちます」。
- 下部の帯：左に「シーン 12・人物 5・ロケ地 4」と「要確認 3 が残っています」、右に主ボタン「確定して香盤表を作る」。要確認が残っていても確定できる。
- 柱が一つも見つからないとき：全文を1シーンにして、上部に「柱が見つかりませんでした。シーンの区切りで『この行で分割』を押してください」。

### 9.4 Excel・CSV の列の割り当て（取り込み確認の Excel の場合）

取り込みで Excel・CSV を選ぶと、取り込み確認（`/p/:pid/import/:draftId/review`）が列の割り当ての形で開く。手順を一枚の画面に上から並べ、前の手順に戻って直すと下が更新される（ページを分けたウィザードにしない。全体を見ながら割り当てたいため）。

| 手順 | 内容 |
|---|---|
| 1 ファイル | .xlsx・.csv・「表を貼り付ける」（Excel や LLM の出力からコピーした表）。シートの選択。CSV の文字コードは自動で判定し、UTF-8／Shift_JIS を選び直せる |
| 2 見出しの行 | 先頭30行のプレビューで行を押して「見出しの行」にする。その上の行を「カテゴリの行」（任意）に指定でき、結合セルは右へ広げて読む |
| 3 列の割り当て | 列ごとのセレクト：取り込まない／話／シーン番号／柱（見出し）／ロケ地／時間帯／屋内外／ペラ／尺（秒）／撮影見積（分）／撮影日／シーンの備考／要素の列（カテゴリを選ぶ）。要素の列にした見出しの語が要素名になる。人物のカテゴリはキャスト、エキストラのカテゴリはエキストラとして人物も作る。一括の操作「ここから右はすべて人物の列」 |
| 4 印とみなす値 | 要素の列に現れた値と件数（● 820、○ 12、1 3、済 1 など）をチェックで選ぶ。既定は「空でない値すべて」 |
| 5 プレビュー | 取り込み後の香盤表の先頭20行と、問題の一覧（番号が空の行、番号の重複、読めない時間帯と寄せ先の候補「夕方→夕」、読めない撮影日）。問題ごとに「取り込まない」「前の行の続きにする」などを選ぶ |

- KOBAN の公開テンプレートと同じ見出し（`templates/columns.ts`）なら、上部に「KOBAN のテンプレートの書式です。列を自動で割り当てました」と出し、割り当て済みの状態で開く（F2-6・F15-3）。他の書式でも見出しの語（「S#」「シーン」「柱」「D/N」「ペラ」など）から推定し、推定した割り当てには「推定」のラベルを付ける。
- 取り込んだ印の根拠は「Excel 取り込み（ファイル名・シート・セル番地）」。詳細パネルにそのまま出す。
- 下部の帯に「シーン 300・要素の列 142・印 4,812」、右に主ボタン「取り込んで香盤表を作る」。

### 9.5 台本（`/p/:pid/script`）

#### 9.5.1 表示

- 縦書き（`writing-mode: vertical-rl`）で柱・ト書き（3字下げ）・セリフ（話者名と「」）の書式を保つ。横書きにも切り替えられる（F3-1）。
- 上部で版を切り替える（版名・改訂日。任意の版の本文を読める、F3-6）。直近の改訂で変わったシーンの付箋には「＊」。
- シーンの区切りに番号の付箋を出し、押すと香盤表のその行の詳細パネルを開く。
- 香盤表の「台本で見る」から来たときは、根拠の行の範囲を `accent-soft` の地と、行の両側（縦書きでは上下）の 2px の藍の線で示し、そこへスクロールする。
- 本文の鍵がこの端末に無いとき（新しい端末で、まだ承認も復旧コードの入力もしていない）は、本文の代わりに「この端末には本文の鍵がありません」と、「ほかの端末で承認する」「復旧コードを入力する」を出す（`04` 9.3・13.5）。柱・人物・香盤表・総スケ・日々スケは使える。改訂の取り込みもできるが、旧版の本文を読めないので、対応づけは見出しと番号だけで行うことを一文で書く。復旧コードも端末もすべて失った場合は、台本ファイルを同じ版名で取り込み直せば本文が戻ることを、同じ場所に書く。
- 主ボタン：「改訂稿を取り込む」→ 9.2 → 9.5.2 → 9.5.3 → 反映。

#### 9.5.2 対応づけ

旧版のシーンと新版のシーンを行で並べる。各行は「旧 S12 太郎の家・居間 ⇄ 新 S13 太郎の家・居間」と、種類のラベル（同じ／番号が変わった／変更／追加／削除）。自動の対応のうち確からしさが低いものは注意の枠で示す。付け替えはセレクト「対応する旧シーン：…／なし（追加）」で行う（F3-2）。主ボタン「差分を見る」。

#### 9.5.3 差分と影響

| 区画 | 内容 |
|---|---|
| 上部のまとめ | 「追加 2・変更 7・削除 1・番号の変更 5 ／ 影響：撮影日 3日・日々スケ 2件（うち配布済み 1件）・人物 +1・小道具 −2（提案）」。数を押すと左の一覧を絞る |
| 左 | 変わったシーンの一覧（種類で絞れる） |
| 中央 | 選んだシーンの本文の差分。既定は横書き（縦書きでは下線・取り消し線が傍線になって読みにくいため。切り替え可）。追加と削除の見せ方は 1.3 |
| 右 | そのシーンの台帳への影響。話者の増減、ロケ地の変化、要素の追加の提案（チェック既定オン）、要素の削除の提案（チェック既定オフ。外さなければ印は残り、香盤表で「根拠を失った」になる。自動では外さない、F3-3）、撮影日と日々スケへの影響（「撮影2日目 10月21日(水) の日々スケ：出演者に父が加わります（配布済み・版3）」、F3-4） |
| 削除されたシーン | 台帳から消さず、そのシーンの印・撮影日の割り当て・メモを「退避」に置く（F3-5）。退避は総スケの未割当の下と、香盤表の行の絞り込みから見え、別のシーンへ付け替えるか、明示的にゴミ箱へ移す |
| 主ボタン | 「反映する」。ボタンの左に「反映の前の状態を版の履歴に残します」と書く |

反映のあとは「影響の一覧」を出す。撮影日ごとに、変わった点と「日々スケを見る」「配布と確認へ進む」。反映はトーストの「元に戻す」でも戻せ、時間が経ってからは版の履歴から反映前の状態を開ける。

### 9.6 香盤表（`/p/:pid/koban`）

- 構成：レール、本体（ツールバー・表・下部の集計）、詳細パネル。**詳細パネルは既定で閉じる**（U1）。開くと幅 22rem で表が狭まり、1280px 未満では表の上に重ねる。
- ツールバーとグリッドの振る舞いは第8章。
- **下部の集計**（高さ 32）：シーン数、ペラ合計、撮影見積の合計、未割当のシーン数、根拠を失った印の数、（台本がある作品では）台本の行なしの印の数、表示中の列数（「150列中32列」）、凡例。数を押すと、その条件で行を絞る。
- **詳細パネル**（`role="complementary"`、`aria-label="S12 の詳細"`）：
  - シーンの属性：話、番号、見出し、ロケ地（選択）、時間帯、屋内外、ペラ、尺（本編の長さ、秒、任意）、撮影見積（撮影にかかる時間、分、任意）、撮影日（総スケへのリンク）。尺と撮影見積は別の欄にし、ラベルに意味と単位を書く（C8）。
  - 要素をカテゴリ別に並べ、各要素の行に来歴を書く。「台本 第2稿 12〜14行［台本で見る］」「手入力 10/18 自分」「Excel 取り込み 香盤.xlsx・シート1・G12」「根拠を失った：第2稿で行が消えました［行に結びつけ直す］［外す］」。「外す」はゴミ箱へ移し、トーストで戻せる。「行に結びつけ直す」は台本の画面を開き、行を選ばせる。
  - 要素の追加（名前の検索と、無ければ新しく作る）。
- **空の香盤表から始めた作品**（F2-7）：表の先頭に入力行「番号［　］柱［　］」を置き、Enter で1行増えて次の入力行へ移る。要素の列が無ければ、空状態「人物や衣裳の列を足しましょう」と「列を足す」。
- **シーンが一つも無い作品**：「台本を取り込むか、番号と柱を打ってシーンを足しましょう」と「台本を取り込む」。
- **閲覧のみ**（保管中・別のタブで開いている・アプリが古い）：セルを押しても切り替わらず、編集の操作は無効にし（隠さない）、上部に閲覧のみの帯（9.15）。書き出しはできる。
- **スマホ**：既定は「シーンの一覧」（行＝シーン。下に要素のラベルをカテゴリ順に並べ、来歴の印も付ける。押すと詳細シート）。ツールバーの切り替えで表（44px、固定は話・番号・柱（狭い））。
- 主ボタン：無し（表そのものが作業面。書き出しは副のボタン）。

### 9.7 素材（`/p/:pid/assets?tab=persons|locations|categories|episodes`）

タブは人物・ロケ地・カテゴリと、話を使う作品では話。どれも PC は一覧＋右の編集パネル、スマホは一覧＋全画面のシート。

**人物**

- 一覧の列：名前、役名、区分、部署、NG日の数、出演シーン数、連絡先の有無。区分で絞れ、名前で探せる。主ボタン「人物を足す」。
- 編集：名前（必須、1〜40字）、役名（任意、40字）、区分（キャスト／エキストラ／スタッフのラジオ。説明「スタッフは香盤表の列になりません。日々スケの連絡先と、NG日の検査に使います」、F4-6）、部署（任意）、NG日、連絡先（電話・メール・LINE ID）。
- **NG日**：月のカレンダー（日は 44×44）。撮影日には点を付け、日を押して選ぶ。選んだ日にはメモを付けられる。選んだ日がその人の出番のある撮影日と重なると、カレンダーの下にエラーの段階で「10月21日(水) は撮影2日目で、S2・S5 に出番があります」と出す。スタッフは全撮影日に対して検査し、警告の段階で出す。
- 区分をキャスト・エキストラからスタッフに変えるとき：「香盤表の印 12件は消さずに残しますが、表には出なくなります。区分を戻すと元どおり出ます」の確認。
- 人物をゴミ箱へ移すとき：「この人の印 12件も一緒にゴミ箱へ移ります（一緒に戻せます）」。

**ロケ地**

- 一覧の列：名称、住所、座標の有無、使っているシーン数、利用可能時間。上部に、座標の無い屋外のロケ地があれば注意の段階で「座標の無い屋外のロケ地 3（日の出・日の入りを出せません）」。
- 編集：名称（必須、60字）、住所、座標（「住所から探す」は通信が要る。緯度・経度の手入力も可）、地図（地理院タイルを MapLibre で表示し、出典を書く。ピンを動かして位置を直せる。取れないときは地図を出さず住所だけ、`04` 第15章）、利用可能時間（開始・終了。検査は〔P2〕F6-7）、写真、メモ。
- 取り込み確認と同じ「まとめる」操作で、柱から作った候補をまとめられる。

**カテゴリ**：一覧で、並べ替え（ドラッグと「上へ」「下へ」）、名前の変更、表示・非表示、追加（F4-2）。既定のカテゴリは削除できず、非表示にするだけ。カテゴリに色は持たせない（罫線帳の方針。`05` 8.6 の「色」は使わない）。

**話**：番号・題・並び。追加、名前の変更、並べ替え、ゴミ箱へ移す。

### 9.8 総スケ（`/p/:pid/schedule`）

- PC：左に未割当（幅 18rem、地 `sunken`）。上から「どの撮影日にも入っていないシーン N」と「退避」。右に撮影日の列（幅 18rem）を横に並べ、横にスクロールする。ツールバーに「日へ移動」（日付を選んで飛ぶ）と「書き出す」。主ボタン「撮影日を足す」。
- **撮影日の見出し**：
  - 「撮影2日目 10月21日(水)」、主なロケ地、集合 8:00・撤収予定 20:00。
  - 撤収見込み（予定より遅ければ「20:30（30分押し）」、早ければ「19:30（30分巻き）」）。
  - 撮影見積の合計・ペラ合計・出演者数（F6-2）。
  - 日の出・日の入り（屋外のロケ地に座標があるとき）。
  - 配布の状態（「配布済み 版3・確認 5/8」、配った後に変更があれば「再配布が必要」）。
  - 検査の結果を、段階の順に記号＋語＋一文で。エラーがある日は列の枠を 2px の `err` にする。押すと原因の説明と、関係する人物・シーンへの導線。
- **検査**（`05` 3.5 と `03` F6）：

| 検査 | 段階 | 見出しの文の例 |
|---|---|---|
| キャストの NG日 | エラー | 「父（山田）：10/21 NG」 |
| スタッフの NG日（全撮影日に対して） | 警告 | 「照明 鈴木：10/22 NG（スタッフは全撮影日を検査しています）」 |
| 撤収見込みが予定を超える | 警告 | 「撤収見込み 20:30、予定から30分押し」 |
| 同じシーンが複数の日に入っている（部分指定なし） | 警告 | 「S7 が 1日目と3日目に入っています」 |
| 日照（屋外で座標あり） | 注意 | 「S11（夕・外）が日の入り 16:48 の後にかかります」 |
| どの撮影日にも入っていないシーン | 一覧 | 未割当の見出しに件数 |

- **シーン片**：7.4。キーボードでは、片の並び全体で roving tabindex にし（タブ停止は1つ）、↑↓で同じ日の中、←→で隣の日へフォーカスを移す。Alt＋↑／↓でその日の中で並べ替え、Enter・Space で移動先を選ぶシートを開く。
- **移動先を選ぶシート**（U4）：撮影日の一覧（日付・ロケ地・いまの撮影見積の合計・撤収見込み）と、それぞれの日に移した場合の検査の予告（「この日に移すと：父 NG日（エラー）」「撤収見込み 21:10（70分押し）」）。日を選んだあとに位置（先頭・末尾・○○の後）。「未割当に戻す」もここから。
- **組み替えの影響**（F6-9）：割り当てを変えるたびに、本体の下に影響の帯を出す（トーストではなく、次の変更まで残る）。例「この変更で：10月21日(水) の日々スケ（配布済み）出演者に父が加わり、入りが変わる人が2人。10月22日(木) の撤収見込みが30分巻き」と「影響の一覧を見る」「元に戻す」。影響の一覧には、撮影日ごとに変わる日々スケの欄と、影響を受ける人（入り時刻が変わる・出番が増減する）を並べ、配布済みの日には「配布と確認へ進む」を出す。
- **撮影日を足す**ダイアログ：日付（必須）、ラベル（既定「撮影N日目」）、集合・撤収予定（`H:MM`、0:00〜35:59）、主なロケ地。
- **スマホ**：撮影日の縦の一覧と「未割当」のタブ。片を押すと操作のシート（移動先を選ぶ・上へ・下へ・詳細）。長押しのドラッグはしない（縦スクロールと衝突するため）。
- 空状態：「撮影日を足して、シーンを割り当てましょう」と「撮影日を足す」。

### 9.10 配布と確認（配る側、`/p/:pid/days/:did/share`）

- 前提：ログインと通信が要る。どちらかが無いときは理由と代わりの手段（「PDF は今すぐ書き出せます」）を出し、配布の操作を無効にする。
- **初めての配布**：設定を確かめる区画を上に置く。
  - 有効期限（既定は撮影日の2日後の終わり、最長は撮影日の30日後。`04` 11.2）。
  - 電話番号を閲覧者に見せない（既定オン、F8-7）。
  - 名前の一覧に出る人（その日に関わるキャスト・エキストラと、日々スケに載せるスタッフ。`04` 11.3）の確認。名前は配布ごとに振り直した参照で渡し、運営者には誰が確認したかも分からないことを一文で書く。
  - リンクのプレビュー（OGP）には作品名も人名も出ないこと（「日々スケ」と撮影日のラベルだけ。`04` 11.6）を一文で書く。
  - 閲覧者に見える内容のプレビュー（スマホ幅）。
  - 主ボタン「配布する」。
- **配布の後**：
  - リンク（「コピー」）と、LINE に貼るテキスト（10.5。「コピー」と共有シート）。
  - テキストの宛先：全員／未確認の人だけ／この更新で影響を受けた人だけ（F8-6）。選ぶと宛名の行が変わる。
  - 有効期限の延長（最長まで）。
  - リンクの鍵はこの作品の鍵で守られるので、作品の鍵（本文の鍵）が無い端末からは同じリンクに再配布できない。その場合は「新しいリンクを発行して、古いリンクを取り消す」を出す（`04` 11.2）。
  - アクセスコード方式（`04` 11.8。LINE で # が落ちる環境が見つかった場合だけ選べる予備）を選ぶときは、「この方式では、運営者が技術的に日々スケを読めます」と確認ダイアログで示す。既定はリンクだけの方式。
- **再配布**：前の版との差分（時刻・シーン・出演者・場所の変化）をプレビューし、「この差分が、閲覧ページの先頭に出ます」と書く。主ボタン「再配布する（版4）」。
- **確認の一覧**：
  - 表の列は、名前・区分または部署・状態（1.3 の記号と語）・時刻・この更新の影響（「入りが 8:00→7:30」）。
  - 上に「版3：確認 5/8」と確認率の棒。
  - 絞り込み：未確認・前の版・影響あり。
  - 名前を押すと、その人に見える閲覧ページ（自分の入り時刻が先頭）をプレビューする。
- **取り消し**：危険ボタン「配布を取り消す」。確認ダイアログ「リンクを開いた人には『この配布は取り消されました』と出ます。取り消しは戻せません。新しく配布し直すことはできます」。確認の記録は消さない。
- 〔P2〕プッシュ通知・メールでの配布（F8-8）。

### 9.11 配布閲覧ページ（受け取る側、`/s/:shareId`）

スマホの縦（幅 360〜430px）を第一に組む。アプリもアカウントも要らず、LINE のアプリ内ブラウザで開かれる前提である。フォントはシステムのもの、外への通信は暗号文の取得と確認の送信だけにする。テーマは OS のダークに従い、文字の大きさは rem で組んでブラウザの設定に従う。

上から順に：

1. **帯**：作品名（暗号文を開いたあとのページの中だけに出す）、「撮影2日目 10月21日(水)」、「版3・10/20 21:14 更新」。
2. **更新の帯**（版が2以上のとき）：この端末が最後に見た版から（無ければ前の版から）の変更を最大5行。「集合 8:30→8:00」「S5（太郎の家・玄関）が加わりました」「太郎さんの入り 8:00→7:30」。「すべての変更を見る」で開く。地 `accent-soft`、字 `ink`、「更新」のラベル（F8-5）。
3. **名前を選ぶ**（初回）：「あなたの名前を選んでください」。出演者と、部署ごとのスタッフに分けた一覧と検索欄（各行 48）。「名前を選ばずに見る」も置く（その場合は確認を送れない）。選んだ名前はこの端末に覚える（localStorage を try/catch で包み、覚えられなければ毎回選ぶ）。「名前を選び直す」はページの下に置く。
4. **あなたの予定**（名前を選んだ後、F8-2）：入り時刻（Display 2rem 700）、場所、出番（「S2 9:00〜」「S5 11:00〜」）、メモ（衣裳・メイク）。スタッフには部署の集合時刻を出す。
5. **全体**：集合と場所（「地図で開く」は外部の地図アプリ）、日の出・日の入り、撤収見込み、予定（カードにせず罫の行で）、出演者の入り、部署別の集合、各部の準備物、食事・移動、注意事項、連絡先（電話は既定で伏せ、肩書きと名前だけ）。
6. **下部に固定**：主ボタン「確認しました」（高さ 48、幅いっぱい、下の安全領域の上、F8-4）。押すと「版3を確認しました 21:20」の表示に変わってボタンは消え、新しい版が来ると「更新を確認しました」として再び出る。通信が無くて送れなかったときは「通信できたら送ります」と出し、復帰したら送る。ページの下端に固定ボタンの高さぶんの余白を入れ、最後の行が隠れないようにする。

| 状態 | 表示 |
|---|---|
| 読み込み中 | 罫だけの骨組み |
| 期限切れ | 「この配布は期限が切れました。配布した人に新しいリンクを頼んでください」 |
| 取り消し済み | 「この配布は取り消されました」 |
| 鍵の欠け（URL の # 以降が無い） | 「リンクが途中で切れています。LINE で開いた場合は、メニューの『ブラウザで開く』を試してください」 |
| 通信なし | 前に開いた版を出し、上に「通信できないため、前に開いた版3を表示しています」 |
| 開いている間に新しい版が出た | 画面に戻ったときに確かめ、上部に「新しい版があります」と「読み込む」 |

印刷用の CSS で A4縦1〜2枚に収める。配る側がアクセスコード方式（`04` 11.8）を選んだ配布では、名前を選ぶ前に8桁のコードの入力（数字のキーボード、8つの枠ではなく1つの欄、`inputmode="numeric"`）を置く。5回失敗すると15分止まることを、失敗の文言に書く（「コードが違います。あと2回で15分間入力できなくなります」）。

### 9.12 上書きの確認と復元（`/p/:pid/overwrites`）

データ保全の最後の受け皿である（F9-2、C10）。

- **入口**：
  - アプリバーの「上書き N」（未確認があるときだけ出る）。
  - 同期で上書きが起きたときのトースト（「別の端末の変更で、S12 の撮影見積が上書きされました」と「確かめる」）。トーストは5秒で消えるが、件数はアプリバーに残る。
  - 作品設定のリンク。
- **一覧**（新しい順）：1件ごとに、いつ、どの端末・誰の変更か、何が（「S12 の撮影見積」「父の NG日」「撮影2日目の集合」と、作品の中の言葉で）、上書きされた値 → いまの値。
- **操作**：
  - 列ごとの旧値に「この値に戻す」（`04` 8.8）。戻すこと自体が新しい変更として同期され、記録に残る。戻す直前の状態は版の履歴にも残る。
  - 「このままにする」。確認済みにするだけで、記録は消さない。
  - 行ごとゴミ箱へ移されていた場合は「ゴミ箱から戻す」。
- **同期できない項目**：同期で5回続けて失敗した行（`E_PROJECT_MISMATCH` など、`04` 第18章）も、同じ画面の別の区分に出す。操作は「もう一度送る」「JSON に書き出す」。
- **絞り込み**：未確認／すべて。記録は作品が存続する間すべて残す（`03` 第8章、C1）。古い記録を消すボタンは置かない。
- 上書きされた欄・セルには、確認済みにするまで 1.3 の印を出す。
- 空状態：「上書きされた項目はありません」。

### 9.13 版の履歴（`/p/:pid/history`）

- 入口：作品一覧のメニュー、作品設定。
- 一覧：日ごとの版と、出来事の前の版（改訂の取り込み前・データの移行前・復元前。`04` 8.10 の種別と残す数に従う）。版の履歴は端末ごとのもので、作品の本体はクラウドにあることを一覧の上に一文で書く。各行は日時、種類、シーン数・人物数・撮影日数と前の版からの増減（「シーン 13（+1）・人物 6（+1）・撮影日 3（±0）」、F9-1）。
- 操作：「この版を新しい作品として開く」（「傘を返す（10/18 の版）」という新しい作品を作って開く。いまの作品は変えない）と「JSON に書き出す」。いまの作品を過去の版で上書きする操作は作らない。
- 日次の自動保存で、出来事の前の版を消さない（種別ごとに別の枠で持つ、C11）。
- 主ボタン：無し。

| 退会 | 下記 |

**復旧コード**（F10-3）

- 発行の時期：初めてログインしたとき（本文を同期する鍵を作るとき）。ログインしない利用者には、本文が端末から出ないので発行しない。
- 流れ：
  1. 説明「この端末をなくしたときや、別の端末で使うときに、台本の本文を読むために要ります。運営者は本文を読めないので、このコードが無いと本文を戻せません。コードも端末もすべて失ったときは、台本ファイルを同じ版名で取り込み直せば本文が戻ります。香盤表などの台帳は失われません」。
  2. コード（120bit の乱数を 24字で表し、4字ずつ区切る。等幅、1.375rem、`ink`）と「コピー」「テキストで保存」「印刷」。
  3. 確かめ「コードの最後の4字を入力してください」。
  4. 完了。
- 「あとで」も選べるが、その場合は設定と作品一覧の上部に注意の段階で「復旧コードの保管が済んでいません」を出し続ける。
- 新しい端末では、ログインのあと二つの道を出す（`04` 9.3）。
  - **ほかの端末で承認する**（鍵を持つ端末があるとき）：新しい端末と既存の端末の両方に、同じ6桁の確認番号を大きく（等幅、2rem）出し、「両方の画面の番号が同じなら、既存の端末で『承認する』を押してください」と書く。番号が違うときは「承認しない」を押させる（すり替えを防ぐため）。要求は10分で切れ、残り時間を出す。
  - **復旧コードを入力する**（鍵を持つ端末が無いとき）。
  - どちらもしないで使い始めることもでき、その間は本文の欄に 9.5.1 の案内を出す。構造のデータはそのまま使える。

**ログアウト**：「この端末の作品を残す（自分だけが使う端末）」と「この端末から消す（共有の端末）」を選ばせる。同期待ちがあるときは、消す前に送り終えるか書き出すよう促す（`08` 4.3 の共有端末の指摘）。

**退会**（F16-2）

1. 説明：消えるもの（アカウント、クラウドの作品・配布・確認の記録）、選べるもの（この端末の作品）、戻せないこと。
2. 書き出しの案内：「すべての作品を JSON に書き出す」と、作品ごとの PDF・Excel へのリンク。書き出した作品には印を付ける。
3. この端末のデータ：「この端末からも消す」／「この端末には残す（ログインせずに使い続ける）」。
4. 最終確認：メールアドレスの入力と、危険ボタン「退会する」。
5. 完了の画面。

〔P2〕有料のプランがあるときは、解約の案内を最初に出す。

**作品設定**：題名・種別・撮影期間・話を使う、時間の既定（準備・移動・メイク・撤収の余裕・1ペラあたりの分・既定の昼食の時刻と長さ。それぞれ意味と既定値を書く）、保管の切り替え（進行中にする／保管する）、日々スケの電話番号を伏せる（既定オン）、本文をこの端末だけに置く（F10-5。切り替えたときに何が起きるかを書く）、タイムゾーン、版の履歴・上書きの確認へのリンク、作品をゴミ箱へ移す（危険ボタン）。〔P2〕カット番号の書式、メンバー、AI の下書き。

## 10. 帳票

### 10.1 共通

- **書き出しダイアログ**：帳票の種類、用紙（香盤表は A3横（既定）／A4横、総スケは A4横（既定）／A3横、日々スケは A4横（既定）／スマホ幅、ほかは A4縦。`04` 14.1）、範囲（話・撮影日・カテゴリ）、電話番号を載せるか（作品設定に従う）、形式（PDF／Excel）。生成中は進捗と「やめる」。PDF は端末内で作るのでオフラインでも出せる（フォントが無いときは 9.15）。
- 余白は上下左右 10mm（`05` 9.1）。字は 9pt 以上（印刷物の最小）。白地に墨で、表の見出し行だけ `#ECEAE4`、食事・撤収の行は `#F5F4F0`（どちらも墨の字で 14.46・15.80）。罫は 1px の `#6B675F`（白地に 5.63）、上段と下段の区切りは 2px／1px の `#1B1A18`。数字は右揃え。モノクロ印刷で読めることを優先する。

- 改訂で変わったシーンには「＊」を印刷し、脚注に「＊ 第2稿（10/18）で変更」と書く。根拠の状態・上書き・〔P2〕提案の印は印刷しない（画面で片付けるものなので、印はすべて ● で出す）。

### 10.2 香盤表（A3横・A4横）

固定列は `03` F5-1 に合わせて話と撮影見積を加えた。幅（mm）は、話 8・番号 10・柱 50（A4 は 40）・時間帯 10・屋内外 8・ペラ 10・撮影見積 10・撮影日 14。要素列は1列 7mm で、見出しは文字を1字ずつ縦に積んで描く。行の高さは 6mm。表題の帯 12mm・縦書きの見出し 約25mm・フッター 6mm を除いた高さに行を詰める。

| 用紙 | 版面（余白10mm） | 固定列 | 要素列／ページ | 行／ページ |
|---|---|---|---|---|
| A3横 420×297 | 400×277 | 120mm（単発作品は話を除き 112mm） | (400−120)÷7 ＝ 40列（単発 41列） | (277−43)÷6 ＝ 39行 |
| A4横 297×210 | 277×190 | 110mm（単発 102mm） | (277−110)÷7 ≒ 23列（単発 25列） | (190−43)÷6 ≒ 24行 |

収まらない列は、固定列を繰り返した次のページに出す。ページの見出しに「行 1〜39／列 1〜40（人物）」と範囲を書き、改ページごとに見出し行を繰り返す。印は「●」を中央に置く。

### 10.4 スマホ幅の日々スケ（PDF）

A4横の PDF をスマホの幅 390px に合わせて開くと、9pt の字は約 4.2px になり読めない（U11）。そこで、配布リンクを使わずに PDF を LINE やメールで送る人のために、スマホ幅の縦長を用意する（F15-2）。

- 用紙は 90×160mm の縦長（`04` 14.1。幅 255pt）で、内容が多ければ同じ大きさのページを重ねる。余白 5mm。
- 字は本文 10pt、見出し 12pt 700、集合 20pt 700、最小 9pt。390px の画面に幅を合わせると 1pt が約 1.53px になり、10pt は約 15.3px、9pt は約 13.8px で読める。
- 並びは配布閲覧ページの「全体」と同じ（個人の欄は無い）。予定は表ではなく、1シーンを2行の罫の行で組む。

### 10.5 LINE に貼るテキスト

F8-3。個人の名前・電話番号・住所を入れない（宛先を絞ったときの宛名の行だけは例外）。リンクは1本。

```
【日々スケ】撮影2日目 10/21(水)
集合 8:00 太郎の家
https://（配布ドメイン）/s/xxxxxxxxxxxxxxxxxxxxxx#k=…
自分の名前を選ぶと入り時間が出ます。見たら「確認しました」を押してください。
```

- 文面は `04` 11.6 と同じ。再配布のときは2行目に「版3に更新：集合が 8:30→8:00 に変わりました」（変更が複数なら「ほか2件」）を入れる。
- 文面は配る側がコピーの前に欄の中で直せる（作品名を足したいときなど）。既定では作品名を入れない（未公開の作品の題名を LINE に流さないため）。
- 宛先を「未確認の人だけ」「影響を受けた人だけ」にしたときは、最後に「まだの方：佐藤さん、山田さん」の行を足す（グループに投げる文なので、名前だけにし、役名・電話は入れない）。
- リンクのプレビュー（OGP）は「日々スケ」と撮影日のラベルだけで、作品名も人名も出さない。
- 住所と電話番号は入れない。ロケ地は名前だけにする（俳優の自宅などがロケ地になることがある）。

## 12. 文言の規則

## 13. アクセシビリティの約束

1. 文字の対比は 4.5:1 以上（24px 以上、または 18.66px 以上の太字は 3:1 以上）、部品の境界は 3:1 以上。どちらも、**実際に置かれた地の上で**満たす。値は第2章・第6章のとおり。
2. 押せるものは 44×44 以上、配布閲覧ページの主な操作と〔P2〕現場モードは 48 以上。例外は PC 高密度の香盤セル（28、`pointer: fine` のときだけ）。
3. 色だけで意味を伝えない。状態は形・語・件数・片付ける場所の4点で出す（1.2）。警告は記号と語を必ず併記し、塗りの濃さでも段階を分ける。赤と緑の対は使わない。
4. 押せるものは本物の `<button>`・`<a href>`・`<input>`＋`<label>` で作る。アイコンだけのボタンには `aria-label`。飾りの SVG は `aria-hidden="true"`。
5. 状態は属性で伝え、名前に重ねない。香盤セルと切り替えは `aria-pressed`、現在の画面は `aria-current="page"`、入力のエラーは `aria-invalid` と `aria-describedby`、保存状態とトーストは `role="status"`、確認率は `<meter>`、香盤表は `role="grid"` と `aria-rowcount`・`aria-colcount`。
6. ドラッグでしかできない操作を作らない。シーン片・列見出し・〔P2〕カットは、キーボードとボタンで「移動先を選ぶ」「上へ」「下へ」ができる。
7. フォーカスは第6章の二重線で、どの地でも見え、固定の見出しや帯に隠れない。
8. 大きさは rem で組み、OS とブラウザの文字サイズに追従する（3.5）。200% まで横スクロールなしで使え、香盤表の固定部分は 8.5 の上限で縮退する。
9. 注記より小さい字（文字100%で12px 未満）は、画面にも帳票にも使わない。帳票の最小は 9pt。
10. 動きは `prefers-reduced-motion` で止める（列への移動のハイライト、ドラッグの戻り、シートの出入り）。
11. トーストはマウスが載っている間とフォーカスがある間は消さず、消えても取り消し・ゴミ箱で戻せる。
12. 強制カラーモード（Windows のハイコントラスト）で、フォーカス・選択・印が消えない（`outline` を残す、記号は `currentColor` で描く）。
13. 検証は、自動検査（axe）と、NVDA・VoiceOver・TalkBack による手動の確認の両方で行う（8.3）。

1. `ShareViewer`：配布閲覧ページ（スマホ）。名前を選ぶ、あなたの予定、更新の帯、全体、下部の「確認しました」と確認後の表示、期限切れ・取り消し・鍵の欠け・通信なしの状態。
2. `Share`：配布と確認（配る側）。初めての配布の設定、LINE のテキスト、再配布の差分、確認の一覧。
3. `ScriptDiff`：改訂の対応づけと、差分と影響（3区画）、反映後の影響の一覧。
4. `ExcelMapping`：Excel・CSV の列の割り当て（手順1〜5を一枚に）。
5. `Assets`：人物の一覧と編集（区分・NG日のカレンダー・連絡先）、ロケ地、カテゴリ、話。
6. `Overwrites`：上書きの確認と復元（同期できない項目の区分を含む）。
7. `History`：版の履歴。
8. `Settings`：ログイン（確認コード）、復旧コードの発行と確かめ、退会の5段、ログアウトの選択、作品設定。
9. `Trash`：ゴミ箱。
10. `MoveSheet`：移動先を選ぶシート（検査の予告つき）。
11. `CallSheetEditor`：日々スケの編集（PC、右にプレビュー）。
12. `States`：各画面の空状態、閲覧のみの帯、別のタブで開いている、オフライン、画像だけの PDF、本文の鍵が無い。
13. `CallSheetPhonePdf`：スマホ幅の日々スケ PDF。`KobanPdf`：香盤表の A3横と A4横（列の分割ページを含む）。
14. `KobanTouch`：タッチの香盤表（44px）と、スマホのシーンの一覧。
15. `TabletPortrait`：768〜1023px のアイコンだけのレールと下からのシート。
16. 主要画面（香盤表・総スケ・日々スケ）のダーク版。

フェーズ2：課金（作品プラン・会社プランの申込み・最終確認画面・特定商取引法の表記）、メンバーと役割、AI の提案の採用、配置図、絵コンテ。
