## 1. 背景と目的

撮影の現場では、香盤表や日々スケを作品の LINE グループに PDF で流すのが主流である。LINE そのものは「一瞬で連絡が出来て、基本的に漏れが無い」と評価されており、不満の対象ではない。不満は、どれが最新版か分からないこと、天候や直前の変更で差し替えが起きるたびに作り直して再連絡すること、送った相手が本当に見たか分からないことにある（`09` 第2章）。

最初の香盤表を作る作業は、一般のLLMでも、AIで香盤を作る国内のサービス（脚本パックン）でもできる。KOBAN は生成では競わない。変わり続ける日々スケを、全員の手元で最新に保ち、確認まで取ることから始める。

目的は三つある。

1. 「最新の日々スケが、全員に届いて、確認されている」状態を、助監督と制作部が数分で作れるようにする。
2. 一人の副業で、壊れても現場が止まらない形で運営する。
3. 制作会社が作品ごとに払う、月10〜30万円規模の事業として成り立たせる。

## 2. 運営の前提と設計の原則

| 前提 | 内容 |
|---|---|
| 体制 | 一人。本業があり、開発と運営に使えるのは週10〜15時間 |
| 対応時間 | 平日の夜と週末。深夜・早朝の即時対応はできない |
| 固定費 | 月1万円前後に抑える |

この前提から、次の原則を全段階に通す。上にあるものほど優先する。

1. **壊れても現場が止まらない。** サービスが止まっても、利用者は直前に配った日々スケを PDF で持っており、LINE 用の文面とともにいつでも書き出して手作業に戻れる。閲覧者はアプリを入れていない。
2. **利用者のデータを失わない。** 削除はゴミ箱を経由し、30日間戻せる。上書きされた版は残す。
3. **預からないものは漏れない。** 最初の段階では台本の本文を預からない。連絡先は電話番号を伏せるのを既定にする。
4. **手がかからない。** 問い合わせが来なくても回る導線（取り込みの見本、エラーの説明、書き出しによる退避）を機能として作る。手作業の運用（請求書の発行、個別の設定）を残さない。
5. **小さく作り、使われたものだけ育てる。**

## 3. 対象ユーザー

| 立場 | 人 | KOBAN でやること | 端末 |
|---|---|---|---|
| 配る人（使い手） | チーフ・セカンド助監督、制作部 | 香盤表を取り込み、日々スケを作り、配り、確認を集め、差し替えを配り直す | 準備は PC、前日夜と現場はスマホのブラウザ |
| 受け取る人 | キャスト、各部スタッフ、事務所のマネージャー | LINE のリンクから自分の入り時間と出番を見て、「確認しました」を返す | スマホ（アプリは入れない） |
| 払う人（買い手） | 制作担当、ラインプロデューサー、制作会社 | 作品ごと、または会社ごとに支払う | PC |

最初の顧客は、検証（段階0）に協力してくれる現場から始める。候補は、配信ドラマ、縦型ショートドラマ、CM・MV である。どれを主にするかは、配布先の人数と差し替えの頻度が大きい現場はどこかを、検証で確かめて決める（`09` B1）。自主映画・学生作品は無料枠で受け入れる。

## 4. 全体像と段階

KOBAN の到達点は、撮影準備の正本となる台帳（オールインクルーシブ）である。香盤表・総スケ・日々スケ・台本・写真・ショットリストまでを一つのデータで持つ。ただし一人で全部を一度には作らない。使われる頻度と痛みの大きい順に、段階ごとに足す。どの段階でも、それまでの段階だけで価値が完結するようにする。

| 段階 | 中身 | 端末 | 目安 |
|---|---|---|---|
| 0 検証 | 聞き取りと、手作業での配布の試行 | 既存の道具 | 4週間 |
| 1 配布と確認（最初の製品） | 香盤表の取り込み、日々スケ、人ごとの配布、確認、差分つきの再配布、LINE の文面、PDF | Web と閲覧ページ | 約3〜4か月 |
| 2 台本と改訂 | 台本の取り込み、改訂の追従、根拠、総スケの検査の充実、版の履歴、編集者の招待 | Web | 約3か月 |
| 3 現場のアプリ | iPhone アプリ。改訂ページや紙の香盤表を撮って取り込む、つながり写真とロケハン写真、今日の予定のウィジェット、電波のない場所での表示 | iPhone | 約4か月 |
| 4 撮る人の道具 | ショットリスト、配置図、ビューファインダー、絵コンテ、iPad の画面、LLM の接続口 | iPhone・iPad | 要望を見て決める |

段階1を Web で始めるのは、配る人の作業は PC とスマホのブラウザで足り、受け取る人はアプリを入れないからである。カメラと端末内の処理が価値の中心になる段階3で、iPhone アプリを出す（`09` 第5章）。

### 入れない機能

| 機能 | 入れない理由 |
|---|---|
| 露出計 | 使うのは撮影部で、KOBAN の主な使い手（助監督・制作部）の仕事ではない。撮影部は専用の露出計やカメラの波形・フォルスカラーで測っており、スマホのカメラでは精度が足りない。無料の露出計アプリも多く、差別化にならない。段階4で撮影部の要望が強ければ、ビューファインダーの「参考の明るさ」として再検討する |
| 予算・精算 | 制作部は会計ソフトと Excel で持っており、台帳とのつながりが薄い |
| AIによる香盤の生成 | 生成はLLMや競合が担える。KOBAN は生成された香盤表を取り込んで回す側に立つ |
| 3Dの配置図、リアルタイムの共同編集 | 一人で作り続けられる規模を超える |

## 5. 用語

| 用語 | 定義 |
|---|---|
| 香盤表 | シーンを行、登場人物・衣裳・小道具などを列にしたマトリクス |
| 総スケ | 全撮影日のスケジュール。各撮影日にどのシーンをどの順で撮るか |
| 日々スケ | 撮影日1日分のスケジュール。集合・場所・シーン順・出演者の入り・各部の準備・連絡先を載せる。海外のコールシートに相当 |
| 配布 | 日々スケを閲覧用のリンクで関係者に渡すこと。更新すると、同じリンクの中身が新しい版になる |
| 確認 | 受け取った人が「確認しました」を返すこと。版ごとに集計する |
| 差分 | 前の版から変わった点（時刻・シーン・出演者・集合場所）。再配布の先頭に示す |
| 拘束時間 | 集合から撤収までの時間。JAC の指針（原則12時間以内、超えたら翌日まで10時間以上空ける）と照らす |

## 6. 業務フロー（段階1）

1. 配る人が、手元の香盤表（Excel・CSV・スプレッドシートの貼り付け）を取り込む。列を「番号・柱・時間帯・人物…」に割り当てる。
2. 撮影日を作り、シーンを割り当てて並べる。集合時刻と撤収予定を入れる。
3. 撮影日を開くと日々スケができる。各部のメモ・食事・注意事項を足す。
4. 配布する。人物マスタの一人ひとりに自分用のリンクができ、LINE に貼る文面が出る。グループ用の共通リンクも選べる。
5. 受け取った人はリンクを開き、自分の入り時間と出番を先頭で見て「確認しました」を押す。
6. 配る人は、確認した人・前の版で止まっている人・未確認の人を一覧で見る。
7. 天候や直前の変更で差し替えるときは、日々スケを直して再配布する。差分が先頭に付き、影響を受ける人と未確認の人だけへの再送文面が出る。
8. サービスが止まっても、配る人はいつでも PDF と LINE 用の文面を書き出して手作業に戻れる。

## 7. 機能要件（段階1）

優先度は MoSCoW（M=必須、S=重要、C=あれば良い）。段階2以降は第8章に要約する。

### A 作品と取り込み

| ID | 要件 | 優先度 |
|---|---|---|
| A-1 | 作品を作り、題名・種別・撮影期間を持たせられる。作品はゴミ箱を経由して削除し、30日間戻せる | M |
| A-2 | Excel（.xlsx）・CSV・スプレッドシートからの貼り付けで香盤表を取り込める。見出し行を指定し、各列を番号・柱・時間帯・屋内外・ページ・人物・衣裳・小道具などに割り当てる。割り当ては作品ごとに覚え、次の取り込みで使い回す | M |
| A-3 | 公開する無料テンプレートの書式と、脚本パックンなど主な競合の書き出し形式は、割り当てを自動で行う | S |
| A-4 | 香盤表がなくても、空の表から番号と柱を打ってシーンを作れる | M |
| A-5 | 取り込み直すと、前回からの変化（増えたシーン・消えたシーン・変わった出演者）を一覧にし、確認してから反映する。消えたシーンに紐づく割り当ては削除せず「未割当」に退避する | M |
| A-6 | 作品全体を JSON で書き出し・復元できる | M |

### B 台帳の最小限

| ID | 要件 | 優先度 |
|---|---|---|
| B-1 | シーン（番号・柱・時間帯・屋内外・ページ・撮影見積）、人物（名前・役名・区分・部署・NG日・連絡先）、ロケ地（名称・住所）、撮影日を持つ | M |
| B-2 | 人物はキャスト・エキストラ・スタッフに分ける。スタッフも配布の対象になる | M |
| B-3 | 香盤表を表示し、印を付け外しできる（取り込んだ表の確認と小さな修正のため） | M |
| B-4 | 撮影日にシーンを割り当て、並べ替えられる（総スケ）。時刻は24時を超える表記（25:30）を許す | M |
| B-5 | キャストのNG日と割り当ての衝突をエラーにする | M |
| B-6 | 撤収見込みが予定を超えたら警告する。拘束時間が12時間を超える日、前日の撤収から10時間空かない日を警告する | S |

### C 日々スケ

| ID | 要件 | 優先度 |
|---|---|---|
| C-1 | 撮影日を選ぶと、シーン順・時間割・出演者の入り時間・ロケ地・各部の準備物を含む日々スケができる | M |
| C-2 | 集合時刻（全体・部署別・人物別）、食事、移動、注意事項、各部のメモ、連絡先を追記できる。手で上書きした値には印を付け、自動の値に戻せる | M |
| C-3 | 集合時刻とシーンの開始時刻の正本は撮影日側に一つだけ持ち、総スケと日々スケで同じ時間割になる | M |
| C-4 | 日々スケを PDF（A4横）で書き出し、印刷できる | M |

### D 配布と確認（中心の機能）

| ID | 要件 | 優先度 |
|---|---|---|
| D-1 | 配布すると、人物ごとの専用リンクを作る。グループに貼る共通リンクも選べる | M |
| D-2 | LINE にそのまま貼れる文面（日付・集合・場所・リンク）を作る。リンクのプレビューには作品名と日付だけを出し、個人情報を出さない | M |
| D-3 | 閲覧ページはアプリもアカウントも要らず、スマホで読みやすく組む。専用リンクで開くと、その人の入り時間と出番が先頭に出る | M |
| D-4 | 閲覧ページから「確認しました」を返せる。版ごとに、確認した人・前の版で止まっている人・未確認の人を一覧にする | M |
| D-5 | 日々スケを更新して再配布すると、同じリンクの中身が新しい版になり、前の版からの差分を先頭に示す | M |
| D-6 | 差分で影響を受ける人と未確認の人だけを選んで、再送用の文面を作れる | M |
| D-7 | 閲覧ページは「PDFで保存」を出し、電波のない場所でも手元で見られるようにする | M |
| D-8 | 電話番号は既定で伏せる。集合場所の詳しい住所は、指定した人のリンクにだけ出せる。閲覧ページには閲覧者の名前を薄く重ねて表示し、転送されたときに出所が分かるようにする | M |
| D-9 | リンクは有効期限（既定は撮影日の2日後）と取り消しを持つ | M |
| D-10 | 配布と確認の状況を、配る人のスマホのブラウザでも見られる | M |

### E アカウントと課金

| ID | 要件 | 優先度 |
|---|---|---|
| E-1 | メールの確認コードでログインする | M |

## 9. 非機能要件（段階1）

| 分類 | 要件 |
|---|---|
| 現場を止めない | サービスが止まっても、配る人は直前の日々スケの PDF と LINE 用の文面をいつでも書き出せる（書き出しは端末に保存した最新の内容から行う）。閲覧ページは配布時に静的に作り、本体と分けて配信する |
| データ保全 | 削除はゴミ箱経由で30日間戻せる。日々スケの版はすべて残す |
| 秘匿 | 台本の本文を預からない。連絡先は役割と設定に応じて伏せる。配布リンクは推測できない識別子と有効期限、取り消しを持つ |
| 権限 | 利用者がサーバーの内部処理を直接呼べない。所有者・プランなどサーバーだけが決める値は、利用者が書き換えられない（`08` T1・T4 の教訓） |
| 通信 | 段階1は、編集に通信が要る構成でよい（クラウドを正とし、端末は表示用の写しを持つ）。電波のない場所での閲覧は PDF で賄う。オフラインでの編集は段階3のアプリで扱う |
| 性能 | シーン300・人物100の作品で、取り込みと日々スケの生成がそれぞれ5秒以内。閲覧ページはスマホの回線で2秒以内に表示する |
| 対応端末 | 配る人：PC の Chrome・Safari・Edge、スマホの Safari・Chrome の最新2版。受け取る人：LINE のアプリ内ブラウザを含むスマホのブラウザ |
| アクセシビリティ | 文字のコントラスト比4.5:1以上、タッチ対象44px以上、OS の文字サイズに追従、色だけで意味を伝えない |
| 個人情報 | 個人情報保護法に沿う。電気通信事業法の外部送信規律への該当を確認し、必要な公表を行う |

## 10. データ（段階1の概略）

```
Project（作品）
├─ Scene: 番号, 柱, 時間帯, 屋内外, ページ, 撮影見積(分)
├─ Element / SceneElement（印）: (シーン, 要素)で一意
├─ Person: 名前, 役名, 区分, 部署, NG日 / 連絡先(別管理)
├─ Location: 名称, 住所
├─ ShootDay: 日付, 集合, 撤収予定 / 割り当て: シーン, 並び
├─ CallSheet（日々スケの上書き分）, CallSheetVersion（配布した版）
├─ Share: 人ごとのリンク, 有効期限 / Ack（確認）: 人, 版, 日時
└─ ImportMapping（取り込みの列割り当て）
```

台本の本文は持たない。

## 11. 画面（段階1）

| 画面 | 主な内容 |
|---|---|
| 作品一覧 | 作品カード、新規作成（Excel／貼り付け／空から）、ゴミ箱 |
| 取り込み | ファイル選択または貼り付け、列の割り当て、前回からの変化の確認 |
| 香盤表 | 取り込んだ表の確認と、印の小さな修正 |
| 素材 | 人物（区分・NG日・連絡先）、ロケ地 |
| 総スケ | 撮影日、シーンの割り当てと並べ替え、NG日・撤収・拘束時間の警告 |
| 日々スケ | 自動の内容と上書き、PDF |
| 配布と確認 | 配布、LINE の文面、確認の一覧、再配布と差分、再送の文面 |
| 閲覧ページ（アプリ外） | 自分の入り時間と出番、全体の予定、確認ボタン、PDF で保存 |
| 設定・アカウント | ログイン、プラン、請求、退会 |

## 12. 料金

| プラン | 価格（税込） | 内容 |
|---|---|---|
| 無料 | ¥0 | 進行中の作品1本まで。配布先は10人まで。全機能 |
| 作品プラン | ¥19,800／作品 | 配布先・撮影日の上限なし。作成から撮了後3か月まで編集でき、以後は閲覧と書き出しのみで保存し続ける |
| 会社プラン | ¥29,800／月 | 作品数・配布先の上限なし。複数の作品を並行する制作会社向け |

無料枠を配布先の人数で区切るのは、KOBAN の価値が「何人に、何回配り直したか」に比例するからである。小さな自主作品は無料のまま使え、関係者の多い現場は払う理由がある。価格は脚本パックン（6か月で¥30,000、税別）と比べて安すぎない水準に置く（`09` B10）。最終的な価格は、段階0の価格感度の聞き取りと事前申込みで決める。

作品プランと会社プランは、どちらもカードと請求書で払える。請求書は手作業にせず、発行・振込の確認・催促まで自動で回す。適格請求書を出すため、個人事業主としてインボイスの登録を行う。

### 売上の見込み

```
月の売上 = 作品プランの新規件数 × ¥19,800 ＋ 会社プランの契約数 × ¥29,800
```

月に作品プラン8件と会社プラン3社なら、約¥25万（税込・決済手数料前）になる。作品プラン8件は、無料枠を超える作品が月約32本あり、その4本に1本が払う、という仮定に当たる。仮定は段階1の実績で置き直す。

## 15. リスクと対策

| リスク | 対策 |
|---|---|
| 深夜・早朝の障害に一人で対応できない | 原則1（現場を止めない）。閲覧ページを本体と分けて配信し、障害時はいつでも PDF と LINE の文面で手作業に戻れる。利用規約で責任の範囲を限定する |
| 本業との両立が崩れ、開発が止まる | 段階ごとに価値が完結する範囲で区切り、止まっても既存の利用者が困らないようにする |
| 配布リンクから撮影場所と入り時間が漏れる | 人ごとのリンク、住所の出し分け、名前の透かし、有効期限と取り消し（D-8・D-9） |
| 汎用LLM＋スプレッドシートで足りてしまう | 段階0で比べ、差が出るのが配布と確認であることを確かめてから作る |
| 競合（脚本パックン・SUKETTO）が配布と確認を足してくる | 競合の書き出しを取り込める入口にし、競合と併用される位置を取る。配布先が増えるほど効く使い方に早く入り込む |
| 推進役の助監督が作品ごとに去る | 作品のデータを助監督が次の作品へ持ち出せる（型の複製・書き出し）。費用は作品ごとに会社が払う |
| 価格が合わない | 段階0の聞き取りと事前申込みで決める |
| 副業の規定・特定商取引法の表示 | 本業の副業規定を確認する。住所・電話番号の表示は、バーチャルオフィスなどで自宅を出さずに済む方法を使う |
