## 1. 背景と目的

海外では映画のプリプロダクションに Cadrage（構図確認）、Scriptation（台本ブレイクダウン）、
Shot Designer（配置図）、StudioBinder（スケジュール・各種表）、CineFlo（コールシート配布）の
5本を使い分けるのが定番だが、いずれも日本語UIを持たず、相互にデータ連携がない。
日本語で同じ領域を一貫して扱う製品は Creators Note（iOS限定）しかない。

本プロダクトは、日本の制作慣行の中心にある「香盤表」をデータモデルの背骨に据え、
台本の取り込みから香盤表・総スケ・日々スケ・ショットリスト・配置図・構図写真・
現場の消し込みまでを一つのデータで貫く、日本語のプリプロダクション統合アプリである。

目的は三つ。助監督・制作部がExcelで繰り返している転記と作り直しをなくすこと。
台本改訂時に全成果物を一度に追従させること。個人が無料で使い始めて現場に持ち込み、
配布が必要になった段階で作品単位の有料プランへ移る事業として成立させること。

## 2. 製品コンセプト

ひとことで言えば「台本を入れると香盤表ができ、香盤表から撮影日と当日の全部が出てくる」。
日本の助監督が頭の中と Excel でやっている工程を、一つの表の三つの見え方として
実装する。

## 3. 対象ユーザー

| ペルソナ | 役割 | 主な利用場面 | 利用端末 |
|---|---|---|---|
| 助監督（セカンド・サード） | 香盤表・総スケ・日々スケの作成と更新、現場進行 | 準備期間はPC、現場はスマホ | PC/タブレット、スマホ |
| 監督 | ブレイクダウン、ショットリスト、配置図、構図写真、絵コンテ | ロケハン、準備、現場 | スマホ、タブレット |
| 制作部（制作進行・ラインP） | 人物・連絡先管理、ロケ・NG日調整、日々スケの配布と既読確認 | 準備期間、前日夜 | PC、スマホ |
| 撮影部・照明部 | 配置図と構図写真の閲覧、ショットの進捗 | 現場 | スマホ |
| キャスト・各部スタッフ | 日々スケの閲覧のみ | 前日夜、現場 | スマホ（LINE経由のリンク） |

主たる顧客セグメントは、自主映画・短編、縦型ショートドラマ、小規模CM・MV、
専門学校・大学の映像学科である。大規模商業映画は初期対象外とする。

## 4. スコープ

### 4.1 やること
台本の取り込みと縦書き表示、改訂管理。ブレイクダウン（人物・場所・衣裳・小道具・特機など）。
香盤表の自動生成と編集。総スケ（撮影日割り）。日々スケ（当日の香盤＝コールシート）の
生成と配布、既読確認。ショットリスト。俯瞰配置図（ブロッキング）。簡易ビューファインダーと
ロケハン写真。絵コンテの自動下書き。現場モード（消し込み・繰り越し・日報）。
PDF/Excel書き出しとExcelテンプレートからの取り込み。作品単位のメンバー管理と権限。

### 4.2 やらないこと（初期版）
予算・精算管理。脚本の執筆エディタ（取り込み専用）。正確なレンズデータベースを持つ
ビューファインダー（簡易版のみ）。3D配置図。動画編集・ポストプロダクション。
リアルタイム共同編集（作品単位の最終更新優先で足りる）。AI自動ブレイクダウンは
第3フェーズまで保留。

## 5. 用語

| 用語 | 定義 |
|---|---|
| 香盤表 | シーンを行、登場人物（および場所・衣裳・小道具）を列にしたマトリクス。出演の有無を印で示す。日本のブレイクダウン兼スケジュール原票 |
| 総スケ | 全撮影日のスケジュール。各撮影日にどのシーンをどの順で撮るかを示す |
| 日々スケ | 撮影日1日分のスケジュール。集合時刻・場所・シーン順・出演者・各部の準備事項を載せる。海外のコールシートに相当 |
| ブレイクダウン | 台本を読み、シーンごとに必要な要素（人物・場所・衣裳・小道具・車両・特機・エキストラ等）を抽出する作業 |
| ショットリスト | シーン内のカット割り一覧。カット番号・サイズ・アングル・動き・レンズ・見積秒数を持つ |
| 配置図（ブロッキング図） | 俯瞰で人物・カメラ・照明の位置と動線を描いた図 |
| 構図写真 | ビューファインダーで撮影した、画角・アスペクト比を再現した写真 |
| 絵コンテ | カット番号・画・内容・セリフ・秒数を縦に並べた日本式のストーリーボード |
| 改訂稿 | 台本の版。改訂日と版名（白・青・ピンク等の慣行は任意）を持つ |
| NG日 | キャスト・スタッフが出られない日 |

## 6. 業務フロー

### 6.1 現状（As-Is）
台本（PDF/Word/縦書きテキスト）を読み、助監督がExcelで香盤表を手入力する。香盤表を
コピーして総スケを作り、撮影日ごとに日々スケを作ってPDF化し、LINEやメールで配る。
監督は別途ショットリストと絵コンテを作り、ロケハン写真はスマホのカメラロールに散在する。
台本が改訂されると、香盤表・総スケ・日々スケ・ショットリストをそれぞれ手で直す。

### 6.2 目標（To-Be）
1. 台本を取り込む → シーン一覧と人物・場所が自動抽出される
2. ブレイクダウンで要素を補う → 香盤表が自動生成される
3. 香盤表のシーンを撮影日に割り当てる → 総スケになる（NG日の衝突は即警告）
4. 撮影日を開く → 日々スケが自動生成され、集合時刻と各部メモを足して配布する
5. 監督はシーンごとにショットリスト・配置図・構図写真を作り、同じシーンに紐づく
6. 現場では当日のすべてがスマホに出て、撮了を消し込むと進捗が共有される
7. 台本改訂時は差分を取り込み、影響箇所が強調された状態で全成果物が更新される

| F14-3 | AI機能は既定で無効とし、有効化時に台本が外部送信されることを明示して同意を取る。学習利用はしない | M（AI実装時） | 3 |

## 8. 非機能要件

| 分類 | 要件 |
|---|---|
| データ保全 | 利用者のデータを失わないことを最上位原則とする。削除はすべてソフト削除で30日復元可。自動処理（同期・改訂取り込み）が本文を黙って消す経路を作らない。改訂取り込みで対応シーンが消えた成果物は「未割当」に退避する |
| オフライン | 現場モードと閲覧は完全オフラインで動く。端末ローカルを真実の源とし、クラウドは複製。復帰時に作品単位で同期し、衝突時はローカルを捨てない |
| 同期 | 作品単位の最終更新優先（LWW）。リアルタイム共同編集は初期対象外。同一作品を複数人が編集する際はフィールド単位のマージを第2フェーズで検討 |
| 性能 | シーン300・人物100・カット2,000の作品で香盤表の表示が2秒以内、編集反映が200ms以内。PDF生成は10秒以内 |
| セキュリティ | 通信はTLS。配布リンクは推測不能なトークン、有効期限、取り消し可。連絡先はロールに応じてマスク。保存データは暗号化（クラウド側） |
| 個人情報 | クルー・キャストの連絡先を扱うため個人情報保護法に沿う。利用目的の明示、第三者提供なし、海外リージョン利用時の情報提供、退会時の削除。プライバシーポリシーをアプリ内と公開サイトに掲示 |
| 法務 | 特定商取引法表記（事業者、価格、支払時期、解約条件、継続課金の最終確認画面）。ストア内課金はApple/Googleの規約に従う |
| 対応端末 | Web（Chrome/Safari/Edge最新2版）、iOS 16以上、Android 10以上。PC/タブレットの大画面と、スマホの縦画面の両方に最適化 |
| 言語 | 日本語を第一言語とし、UI文言は英語も同形で持つ（将来の多言語化の余地）。縦書きは日本語台本のみ |
| アクセシビリティ | 文字サイズ変更に追従、コントラスト比4.5:1以上、現場向けのダークモード |
| 可用性 | クラウド停止時もローカルで全機能が使える。配布リンクの閲覧は静的配信でクラウド本体と分離 |
| 容量 | 無料枠は作品あたり1GB（写真を含む）、有料枠は10GB。写真は端末側で長辺2,048pxに縮小して保存 |

## 9. データモデル（概略）

```
Workspace
└─ Project（作品）: id, title, type, shootStart, shootEnd, deletedAt
   ├─ Member: userId, role(admin|editor|viewer)
   ├─ ScriptVersion（改訂稿）: id, name, revisedAt, source(file), text
   │   └─ Scene: id(安定ID), number, heading, location→LocationRef, timeOfDay, intExt,
   │            pages, estSec, body, notes[]
   ├─ Person（人物マスタ）: id, name, roleName, dept, contact{tel,mail,line}, ngDates[], visibility
   ├─ Location（ロケ地）: id, name, address, lat, lng, photos[], availableFrom, availableTo
   ├─ Element（ブレイクダウン要素）: id, category, name, sceneIds[]
   ├─ ShootDay（撮影日）: id, date, callTime, wrapTime, sceneOrder[sceneId], notes, callSheet{...}
   │   └─ CallSheet（日々スケ）: version, generatedAt, overrides, distribution{linkToken, expiresAt, reads[]}
   ├─ Shot（カット）: id, sceneId, number, size, angle, move, focalLength, desc, estSetupSec, estTakeSec,
   │        status(todo|done|hold), cameraMarkId, photoIds[]
   ├─ BlockingDiagram（配置図）: id, sceneId, background, items[{type, x, y, rotation, label, path[]}]
   ├─ Photo（構図・ロケハン写真）: id, uri, focalLength, sensor, aspect, heading, lat, lng, takenAt,
   │        sceneId?, shotId?, locationId?
   └─ Storyboard（絵コンテ）: id, sceneId, frames[{shotId, imageId?, text, dialogue, sec}]
```

香盤表は独立したエンティティではなく、Scene×Person（Element）の射影として常に導出する。
総スケは ShootDay.sceneOrder、日々スケは ShootDay の射影に手入力の overrides を重ねたもの
とする。これにより「一つの表の三つの見え方」を実現し、改訂時の追従は Scene の安定IDで保証する。

## 11. 技術方針（案）

| 項目 | 方針 |
|---|---|
| アーキテクチャ | オフラインファースト。端末ローカルDBを真実の源とし、クラウドは作品単位で同期する複製 |
| クライアント | 単一コードベースでWeb・iOS・Androidへ展開する（React Native＋Web、またはFlutter。カメラ・GPS・オフラインが要るためPWA単体では不足）。既存プロダクトとは別リポジトリで開始する |
| バックエンド | 認証・同期・配布リンク配信のみを持つ薄い構成。マネージドBaaS（Supabase等）で開始し、ランニングコストを月数千円以内に抑える |
| PDF生成 | 端末側で生成し、サーバー負荷と個人情報の送信を避ける |
| 台本解析 | 柱・ト書き・セリフの日本式書式を規則ベースで解析し、誤りは手修正で吸収。AI解析は第3フェーズ |
| 地図・天気・太陽 | 天気と日の出入りは外部APIを利用し、未設定・未取得でも機能が壊れない縮退動作を保証する |
| 配布リンク | 静的に生成したHTMLをCDNから配信し、本体停止時も閲覧できる |

## 15. リスクと対策

| リスク | 対策 |
|---|---|
| Excel文化からの移行が進まない | Excelテンプレートの取り込み・書き出しで往復を保証し、「Excelの上位互換」として入る |
| 台本書式のゆらぎで自動分割が失敗する | 規則解析＋手修正を前提に設計し、失敗例を集めて規則を育てる |
| ビューファインダーの精度不足への不満 | 「簡易」と明示し、Cadrage/Artemis写真の取り込み連携で補う。正確版は要望が集まれば買い切りIAPで検討 |
| 連絡先の漏えい | 配布リンクの期限・取り消し・マスク、閲覧者ロールで連絡先一覧を非表示、監査ログ |
| 市場が小さく単価も低い | 少人数運営とBaaSでランニングコストを抑え、作品プランで制作会社から回収する |
| Creators Note や海外勢の日本語化 | 香盤ハブ・改訂追従・現場モードの統合体験で差別化し、無料テンプレートで検索を先に取る |
