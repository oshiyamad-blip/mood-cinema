## 1. 結論

実装に入る前に、三つの点で計画を直す必要がある。

一つ目は**競合の前提が崩れたこと**。「日本語で香盤表を一貫して扱えるのは Creators Note だけ」という調査の結論は誤りだった。2026年6月に「脚本パックン」が正式リリースされている。台本の PDF を AI で読み込み、キャスト・ロケ地・小道具・D/N を抽出して、香盤表と撮影スケジュールを作るクラウドサービスである。最安プランは「ショートドラマ・CM・短編向け」の月¥5,000（税別、1香盤ボード）で、改善提案 P1 が最初の顧客に選んだ層と、作品プランの価格帯の両方に正面からぶつかる。「AI学習対象外」「データ暗号化」もすでに掲げている。

二つ目は**同期と権限の設計に、致命的な穴が4つあること**。サーバー関数を誰でも直接呼べる、送らなかった列が空で上書きされる、1行の異常で同期が永久に止まる、編集者が作品の所有者を書き換えられる、の4つで、どれもデータの喪失か乗っ取りにつながる。

三つ目は**香盤表の画面が想定規模に耐えないこと**。1440幅の画面で見える人物列が約11列しかなく、300シーン×100人の香盤表で Excel を置き換えるという合格条件を満たせない。

## 4. 技術設計

### 4.1 致命的

| # | 指摘 | 失敗の例 | 直し方 |
|---|---|---|---|
| T1 | サーバー関数を誰でも直接呼べる。Postgres は関数の実行権限を既定で全員に与え、Supabase は public スキーマの関数を API として公開する。テーブルごとの upsert 関数には権限の確認が無い | 非メンバーが他人の作品の行を、版番号 `ffff…` で送って上書きし、以後ずっと勝ち続ける | 内部関数を非公開のスキーマへ移し、実行権限を取り消す。公開する RPC だけに権限を与える。`search_path` を空にする |
| T2 | 送られてこなかった列が NULL で上書きされる（`jsonb_populate_record(null::…)`）。挿入では既定値が効かず NOT NULL 違反になる | 古いアプリが新しい列を黙って消す | 更新は現行の行を土台にし、挿入は欠けた列に既定値を補う。アプリのスキーマ版を RPC に渡す |
| T3 | 1行の例外で一括送信の全体が巻き戻り、どの行かも分からない。日々スケの撮影日ごとの一意制約で、普通の使い方でも起きる | 2台で同じ撮影日の日々スケを作ると、その作品の同期が永久に止まる | 行ごとに例外を捕まえて結果を返す。論理的に一意な行は ID を決定的に作る |
| T4 | 編集者が作品の行（所有者・プラン・作成日時・削除）を書き換えられる。端末の作品行には作成日時が無いので、題名を変えるだけでも作成日時が消える | 乗っ取り、作品プランの迂回、無料で編集できる1本が勝手に入れ替わる | 作品の行は専用の関数にし、管理者だけが許可した列だけ書けるようにする |

### 4.2 重大

| # | 指摘 | 直し方 |
|---|---|---|
| T5 | 送信中に編集した最新の版が、拒否の応答で巻き戻る | 送信待ちは送った分だけ消し、端末の版が送った版と同じときだけ上書きする |
| T6 | 同じ版番号の再送を「拒否」と扱い、通信が不安定なだけで偽の衝突になる | 等しい版は受理済みとみなす |
| T7 | 時計が未来へずれた端末の行は、その時刻まで誰も編集できなくなる | サーバーの時計で、未来すぎる版番号を拒否するか丸める |
| T8 | 30日後の物理削除と長期オフラインの端末で、行の復活・分岐が起きる。削除時刻が端末の時計なので、即日の永久削除もあり得る | 削除はサーバー時刻を基準にし、物理削除の後も墓標か基準点を残す |
| T9 | 閲覧者から編集者へ上がっても、過去の連絡先が届かない。下がっても端末から消えない | 役割の変更時に該当テーブルを取り直す・消す |
| T10 | 引き込み漏れを防ぐ勧告ロックの論証が、引き込み側の実装（単一スナップショット、`next` の定義）に依存していて未規定 | 条件を明文化し、引き込みを1文の SQL にする |
| T11 | 同期対象のテーブルへ API から直接書けると、ロック・LWW・履歴・無料制限をすべて迂回される | 直接の書き込み権限を取り消し、読み取りだけを RLS で許す |
| T12 | 論理的に同じ行（香盤のセル、撮影日の割り当てなど）がオフラインで重複し、印が消せなくなる | 決定的な ID にする |
| T13 | 並べ替えキーが同じ2行の間へ挿入すると、`fractional-indexing` が例外を投げる | キーの振り直しか、端末由来の文字を付ける |
| T14 | 作品の登録が冪等でなく、応答が失われると永久に「未登録」になる | 同じ ID・同じ所有者なら成功を返す |
| T15 | 無料プランで、唯一の作品をゴミ箱から戻せない | 復元は権利の判定から外し、編集できる1本を明示的に持つ |
| T16 | Web の複数タブで Lock を奪っても、前のタブが OPFS を握ったままで両方とも使えなくなる | 奪われた側は DB を閉じて手放し、奪った側は再試行する |
| T17 | 課金：権利のビューが全ユーザーの課金状態を漏らす。Webhook の順序・移行・返金・冪等性が不備 | ビューを呼び出し元の権限で動かし RLS を掛ける。事象の時刻で単調性を保ち、返金と移行を扱う |
| T18 | 配布リンク（フェーズ2）：4桁の閲覧コードは暗号文を落とせば手元で総当たりできる。鍵の保存場所と IV の再利用が未規定 | コード方式の性質を明示し、鍵の共有方法と IV を規定する |
| T19 | pdf.js の縦書きの文字片は「高さ＝列の長さ」なので、縦書きの判定と列の束ね方が破綻する | フォントの縦書きフラグで判定し、文字の大きさの中央値で束ねる |

### 4.3 軽微

OTP メールは本番で独自 SMTP が必須（Supabase 標準は送信数が極小）。suncalc には撮影日の正午を渡す。@react-pdf の日本語の折り返しと性能は試作で実測する。上書き履歴が大きな行で膨らむ。日々スケの上書き分を2人が別の欄で直すと片方が丸ごと負ける。共有端末で「データを残す」と、次の人が前の人の作品を自分のアカウントへ上げられる。

### 4.4 台本解析（再現済み）

| 入力 | 現在の判定 | 正しい判定 |
|---|---|---|
| `○ 3丁目の路地` | 番号3、見出し「丁目の路地」 | 番号なし、見出し「3丁目の路地」 |
| `○ 101号室` | 番号101、見出し「号室」 | 見出し「101号室」 |
| `〇田が入ってくる` | 柱 | ト書き |
| `遠くで「おーい」と声がする` | 話者「遠くで」のセリフ | ト書き |
| `花子が小声で「ばか」` | 話者「花子が小声で」 | ト書き、または話者「花子」 |
| `テロップ「三年後」` | 話者「テロップ」 | ト書き（字幕） |
| `太郎（受話器に向かって）「もしもし」` | 一致しない | 話者「太郎」のセリフ |
| `太郎の家・翌朝` | 見出し「太郎の家・翌」、朝 | 見出し「太郎の家」、翌朝 |
| `居酒屋・十六夜` | 見出し「居酒屋・十六」、夜 | 見出し「居酒屋・十六夜」 |

ほかに、閉じない括弧が後続の柱を飲み込む、入れ子の括弧の照合がない、字間を空けた名前（`花　子`）を拾えない、屋内外を1字の部分一致で数えるため人名（山田・森田）にも反応する、がある。話者の判定は、台本全体での出現回数を常に条件にし、括弧のつなぎは柱で止める必要がある。

| U12 | 重大 | 「直射日光の下でもダーク」は逆。日なたでは明るい地に暗い字の方が読める | 現場モードに「屋外（高対比ライト）」と「夜（ダーク）」を用意する |
| U13 | 重大 | OS の文字サイズへの追従を約束しているが、すべて px 固定で、iOS の WebView は自動では追従しない | rem で組み、ネイティブから倍率を受け取る |
| U14 | 重大 | 現場モードの右スワイプで撮了が、戻る操作や縦スクロールと衝突する。表示の切り替えが片手で届かない上端にある | スワイプを既定で切り、切り替えを下部へ移す |
| U15 | 重大 | フォントを Google Fonts から読む前提が、CSP・オフライン・PDF 生成と両立しない | 自前で同梱し、サブセット化の方針と容量の上限を決める。PDF には静的な TTF を使う |
| U16 | 軽微 | モックの数値が計算規則と合わない箇所（見積50分は48分のはず、撤収見込み、予定比）、主ボタンが1画面に2つ、現在のタブの色、文言の揺れ（「入れて」と「入力して」、「2.0p」とペラ、現場の「押し・巻き」）、安全領域の未考慮、など | 個別に直す |

## 7. 改善提案（07）への影響

- **P1（ショートドラマの量産現場に絞る）**は、脚本パックンのスタンダードプランが同じ層を狙っているので、そのままでは真っ向勝負になる。AI での香盤生成で並ぶのではなく、改訂追従・オフラインの現場運用・配布・本文を読めない仕組みで勝てるかを、先に現場で確かめる必要がある。
- **P7（作品ごとの買い切り¥9,800）**は、脚本パックンの月¥5,000（税別）と比べられる。
- **P8（公開前からの集客記事）**は、R2 のとおり検索が空いていないので、効果の見込みを下げる。
- **P3（Web 版のみ・課金なしで先行）**は、R11（Google Play のクローズドテスト14日）と C13（課金画面の欠落）を踏まえると、むしろ妥当性が増す。
- 台本を学習に使わない約束（取りまとめ役の別の検討）は、脚本パックンがすでに「AI学習対象外」を掲げているので、差別化ではなく最低条件になる。本文を端末で暗号化して運営者にも読めなくする仕組みまで入れて、はじめて差になる。
