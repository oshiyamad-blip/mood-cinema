# セキュリティレビュー（serifu-app）

対象：日本語の俳優セリフ練習・オーディション練習アプリ（Flutter, iOS/Android, 完全オンデバイス）。
本書は現状のコードと依存・権限・データ取り扱いをレビューし、対応済み/要対応を整理する。

レビュー範囲：`serifu-app/lib/**`、`pubspec.yaml`、データフロー、権限。
重大度：🔴高 / 🟡中 / 🟢低・情報。

---

## サマリ

このアプリは**バックエンドを持たず、台本処理を端末内で完結**させる設計のため、
攻撃面は小さい。最大の論点は「**マイク音声認識のクラウド送信**」と「**台本内容を含む一時ファイルの残置**」で、いずれも本レビューで対応した。クラウドTTSや課金を将来追加する際の**APIキー管理**が次の重要点。

## 1. 🟡 マイク音声認識のクラウド送信（ハンズフリー）— ✅対応
**問題**：`speech_to_text` はOS標準の音声認識を使うが、端末・OSによっては**音声がクラウド（Google/Apple）へ送られる**。本アプリの売りは「台本をAI学習に使わない・オンデバイス」だが、ハンズフリーで**ユーザーが読んだセリフ（＝台本内容）が外部送信**される恐れがあった。

**対応**：`speech_recognizer.dart` で `SpeechListenOptions(onDevice: true)` を既定にし、可能な限りオンデバイス認識を使用。非対応端末では自動進行が働かないが、**手動の「言えた・次へ」で代替**できる（機能は壊れない）。

**残課題**：プライバシーポリシーに「ハンズフリー利用時、端末がオンデバイス認識に非対応の場合はOSの音声認識（クラウド）が使われる可能性」を明記。設定でハンズフリー自体をOFFにできる現状を維持。

## 2. 🟡 台本を含む一時ファイルの残置 — ✅対応
**問題**：
- 事前合成音声（`line_*.wav/caf`）に相手役セリフ音声が保存される。
- 画像PDFのOCRでページ画像（`ocr_page_*.png`）が一時保存される。
両者とも台本内容を含み、削除されないと端末内に残置していた。

**対応**：
- リハーサル画面 `dispose()` で事前合成ファイルを削除（`_cleanupPreparedFiles`）。
- OCRはページ認識直後に一時画像を削除。

**残課題**：異常終了時の取りこぼしに備え、起動時に temp ディレクトリの自前プレフィックスを掃除する処理を追加すると尚良い。

## 3. 🟢 保存データの暗号化なし
`script_store.dart` は台本をアプリ専用領域に**平文JSON**で保存。OSのサンドボックス＋（iOSの）データ保護で実用上は保護されるが、より厳格にするなら：
- iOS：`NSFileProtectionComplete` 相当のファイル保護属性。
- 端末内暗号化：`flutter_secure_storage`（鍵）＋本文暗号化、または OS のキーチェーン/Keystore。
著作物保護の観点で、将来「重要台本の暗号化保存」をオプション化検討。

## 4. 🔴(将来) クラウドTTS/課金導入時のAPIキー管理
**重要**：クライアント同梱のAPIキーは**必ず抽出される**。将来クラウドTTS（Google/ElevenLabs等）を入れる場合、キーをアプリに埋め込まないこと。
- **対策**：軽量バックエンド（またはサーバレス関数）を**TTSプロキシ**として置き、キーはサーバ側に保持。クライアントは自前の認証付きでプロキシを叩く。
- 課金エンタイトルメント検証も同様にサーバ側（または RevenueCat）で。詳細は `docs/03-monetization.md`。
- 送信は必要最小限（合成対象の行のみ）。Zero Data Retention 設定（`docs/02 §3-8`）。

## 5. 🟡 依存パッケージ（供給網・ライセンス）
現依存：`flutter_tts, file_picker, syncfusion_flutter_pdf, archive, xml, google_mlkit_text_recognition, pdfx, path_provider, speech_to_text, audioplayers`。
- **ライセンス確認**：特に `syncfusion_flutter_pdf` は **Syncfusion コミュニティライセンス**（売上・規模の条件あり）。商用配布前に適合性を必ず確認。条件外なら有料、または別のPDF抽出手段に差し替え。
- **供給網**：`pubspec.lock` をコミットしてバージョン固定（再現性）。依存更新時は変更点をレビュー。
- ML Kit はオンデバイス（モデルは端末/初回DL）。テキストはクラウドに出ない。

## 6. 🟢 入力（巨大・不正ファイル）の扱い
- 解析の正規表現は上限付き（役名 `{1,10}`）でReDoSリスクは低い。
- 非常に大きなPDF/画像はメモリを圧迫しうる。将来、ページ数・サイズ上限と進捗キャンセルを追加推奨。
- 破損ファイルは `try/catch` でUIを止めずにエラー表示する実装になっている（`ScriptStore.load` は破損時に空復帰）。

## 7. 🟢 権限（最小権限）
- 要求権限はマイク（音声認識）とファイル選択のみ。カメラ・位置情報・連絡先などは不要で要求しない＝最小権限で良好。
- 権限の用途文字列は `docs/04-release-runbook.md` に従って明記すること。

## 結論
- 設計レベルでプライバシー（非学習・オンデバイス）が担保されており、攻撃面は小さい。
- 本レビューで**音声認識のオンデバイス優先**と**一時ファイル削除**を実装。
- 次の節目（クラウドTTS/課金）導入時は、**APIキーをクライアントに置かない**ことが必須。
- 公開前に **Syncfusion 等のライセンス適合性**と**pubspec.lock固定**を確認すること。
