# フェーズ3：仕様・画面設計

> 対象アプリ：日本語の俳優セリフ練習・オーディション練習アプリ（iOS / Android, Flutter）
> 本書は MVP（最初の出荷版）の機能仕様・画面遷移・データモデルを定義する。

---

## 1. プロダクト概要

### 1-1. ねらい
俳優・声優・演劇部・オーディション受験者が、**台本を取り込んで相手役をアプリに読み上げさせ、自分のセリフを練習**できるようにする。日本語台本に特化する点が差別化。

### 1-2. MVPのスコープ
**含む：**
- Word/PDFの取り込みとテキスト抽出
- 台本の自動解析（役名・セリフ・ト書き）＋手動修正
- 自分の役の選択
- 相手役の声設定（男性/女性、テンポ）
- ト書きの読み上げON/OFF
- 再生（自分の番はポーズ＋ハイライト、相手役はTTS）
- 端末内蔵TTSでの読み上げ（無料・オフライン）

**含まない（将来フェーズ）：**
- クラウドTTS（高品質音声）課金
- 音声認識によるハンズフリー自動進行
- 暗記モード、自己テープ録画
- クラウド同期・台本共有

---

## 2. ユーザーフロー

```
起動
 └─ ホーム（台本一覧）
      ├─[＋取り込み]→ ファイル選択(PDF/Word) → 解析中… → 解析結果プレビュー
      │                                              └─（必要なら）修正画面
      ├─ 台本を選択 → 台本詳細
      │     ├─[役を選ぶ]→ 自分の役を選択
      │     ├─[相手役の声設定]→ 役ごとに 男性/女性・速度
      │     ├─[ト書き] ON/OFF トグル
      │     └─[練習開始]→ 再生（リハーサル）画面
      └─ 設定
```

## 3. 画面一覧と要素

### 3-1. ホーム（台本一覧）`HomeScreen`
- 取り込み済み台本のカードリスト（タイトル / 役数 / 最終練習日）
- FAB「＋ 台本を取り込む」
- 各カード：タップで詳細、長押しで削除/リネーム
- 空状態：「台本を取り込んで練習を始めましょう」＋取り込みボタン

### 3-2. 取り込み `ImportFlow`
1. **ファイル選択**：`file_picker` で PDF / .docx / 画像 を選択
2. **抽出＆解析中**：プログレス表示（抽出→構造解析）
3. **解析結果プレビュー**：行リスト（話者バッジ＋本文、ト書きは別スタイル）
   - 役名一覧を上部にチップ表示（自動抽出）
   - 「修正する」「この内容で保存」

### 3-3. 解析修正 `ScriptEditScreen`
- 各行の `type`（セリフ/ト書き）をトグル
- 各行の `speaker` をドロップダウンで変更（役名の名寄せ・追加）
- 行の結合/分割（誤分割の修正）

### 3-4. 台本詳細 `ScriptDetailScreen`
- メタ情報（タイトル、登場人物、行数）
- 自分の役セレクタ（単一選択）
- 相手役の声設定への導線
- ト書き読み上げ ON/OFF
- 「練習開始」ボタン

### 3-5. 声設定 `VoiceSettingsScreen`
- 役ごとに：
  - 性別（男性/女性）→ 内蔵TTSの該当ボイスにマップ
  - 速度（0.5x〜2.0x、スライダー）
  - ピッチ（任意）
  - 試聴ボタン（その役のサンプル行を読む）
- グローバル既定（自分の役以外すべてに適用）も用意

### 3-6. リハーサル（再生）`RehearsalScreen`
- 中央：現在の行を大きく表示（話者名＋本文）。前後の行を薄く表示（台本ビュー）。
- **自分のセリフ**：読み上げず一定時間ポーズ。行をハイライトし「あなたの番」を表示。`▶次へ`で進む（手動）／オートポーズ秒数は設定可。
- **相手のセリフ**：設定した声・速度でTTS再生。再生中はその行をハイライト。
- ト書き：ONなら読み上げ（ニュートラルな声）／OFFなら画面表示のみ（またはスキップ）。
- コントロールバー：再生/一時停止、前の行、次の行、頭出し、速度クイック変更、ループ範囲指定。
- 進捗バー（何行目/全行）。

### 3-7. 設定 `SettingsScreen`
- 既定の声・速度
- ト書きの既定動作
- 自分の番の自動進行（手動/秒数指定）
- 言語（UIは日本語既定）
- （将来）プレミアム：高品質音声

## 3-8. データ取り扱い・非学習ポリシー（重要要件）

> 要件：**台本データをAIの学習に使われないようにしたい**。台本は著作物かつ非公開資料のため、これを設計の根幹に据える。

### 方針：プライバシーファースト（既定は完全オンデバイス）
- **MVPは台本データが一切端末から出ない構成**にする：
  - 解析＝**正規表現ルール（端末内）**、読み上げ＝**端末内蔵TTS**。
  - → クラウドに送信しない＝**学習に使われる経路が原理的に存在しない**。これが最強の保証。
- 台本本文の保存も端末ローカル（`sqflite`/`hive`）のみ。サーバ保存しない。

### クラウド機能を足す場合（将来・任意）の原則
高品質音声やLLM解析を**オプトイン**で足す場合に限り、以下を厳守：

1. **「API」プランのみ使用（消費者向けチャットUIは使わない）。** APIは学習非利用が既定。
2. **学習非利用が契約・規約で保証された提供元のみ：**
   - **Anthropic API（Claude）**：入出力を**モデル学習に一切使用しない**。既定で7日後に削除。エンタープライズでは **Zero Data Retention（ZDR, 無保持）** 契約も可。
   - **OpenAI API**：API送信データは既定で**学習に不使用**（不正監視で最大30日保持）。**ZDR** プランあり。
   - **Google Cloud（Vertex AI / Cloud TTS）**：顧客データを基盤モデルの学習に使わないと**契約上保証**。
   - クラウドTTS（Google / Amazon Polly / Azure）も同様にエンタープライズ規約で学習非利用。
3. 可能なら **Zero Data Retention（無保持）設定を有効化**し、送信は最小限（必要な行のみ）に。
4. **明示的な同意UI**：クラウド送信が発生する機能は、初回にダイアログで「どのデータが・どこに送られ・学習に使われないか」を提示し、オプトインを取得。既定はOFF。
5. **送信前のローカル匿名化**（任意）：固有名詞・人名のマスキングオプション。

### UI・運用への落とし込み
- 設定画面に「データの取り扱い」項目を設け、現在のモード（完全オフライン / クラウド利用）を明示。
- クラウド利用ONのときのみ、対象機能にバッジ表示。
- プライバシーポリシーに「台本はAI学習に使用しない」「既定でオンデバイス処理」を明記。

> まとめ：**MVPは完全オンデバイスで“学習されない”を100%保証**。クラウドは将来の任意機能とし、学習非利用が保証されたAPIのみ・オプトインで採用する。

## 4. データモデル

```dart
// 台本
class Script {
  String id;
  String title;
  List<String> characters;   // 登場人物（役名）
  List<Line> lines;          // 全行（シーン分割は将来）
  DateTime importedAt;
  DateTime? lastPracticedAt;
  Map<String, VoiceProfile> voiceByCharacter; // 役→声設定
  String? myCharacter;       // 自分の役
  bool readDirections;       // ト書き読み上げ
}

// 行
class Line {
  String id;
  LineType type;             // dialogue | direction
  String? speaker;           // ト書きはnull可
  String text;
}

enum LineType { dialogue, direction }

// 声設定
class VoiceProfile {
  Gender gender;             // male | female
  double rate;               // 0.5〜2.0（既定1.0）
  double pitch;              // 既定1.0
  String? voiceId;           // 内蔵TTSの具体ボイスID（任意）
}

enum Gender { male, female }
```

**永続化**：MVPは端末ローカル（`sqflite` か `hive`）。台本本文はローカル保存（プライバシー既定）。

## 5. 解析パイプライン（実装観点）

```
ファイル
 → TextExtractor
     - PdfTextExtractor / DocxTextExtractor / OcrExtractor
 → 生テキスト（行配列）
 → ScriptParser
     1) RuleBasedParser（正規表現）：役名・セリフ・ト書きの一次判定
     2) （オプション/将来）LlmParser：曖昧行の補正・名寄せ
 → List<Line> + characters
 → ユーザー確認/修正
 → Script を保存
```

**正規表現の初期ルール（日本語台本の定石）：**
- 役名＋セリフ：`^\s*([^\s「（：:]{1,10})\s*[「：:]\s*(.+)$`
- カギカッコ閉じ無し継続行：直前のセリフへ連結
- ト書き：`^\s*[（(].*[)）]\s*$`、または役名にマッチしない地の文
- 「登場人物」ブロックがあれば役名辞書として優先

> 解析は完璧にならない前提。**必ず確認・修正UIを通す**。

## 6. 再生エンジン抽象化

```dart
abstract class SpeechEngine {
  Future<List<VoiceOption>> voices(String lang);  // 利用可能ボイス
  Future<void> speak(String text, VoiceProfile p);
  Future<void> stop();
  Stream<SpeechProgress> get progress;            // 単語/行ハイライト用
}

class DeviceSpeechEngine implements SpeechEngine { /* flutter_tts */ }
// 将来: class CloudSpeechEngine implements SpeechEngine { /* Google/ElevenLabs */ }
```

MVPは `DeviceSpeechEngine` のみ。インターフェースを切っておくことでクラウド版を後から差し込める。
