# フェーズ4：収益化（マネタイズ）設計

> 対象アプリ：日本語の俳優セリフ練習・オーディション練習アプリ（iOS / Android, Flutter, 完全オンデバイス既定）
> 本書は収益化モデルの比較・価格設定・実装要件・プライバシー整合・段階的ロールアウトを定義する。
> 前提資料：`docs/01-tech-research.md`（TTS料金・「一度合成してキャッシュ」の知見）、`docs/02-spec-and-screens.md`（仕様・非学習ポリシー）。

## 0. 結論（先に要点）

| 論点 | 推奨 | 根拠 |
|---|---|---|
| 主モデル | **フリーミアム + 月額/年額サブスク**（クラウドTTSを主たる有料機能ゲートに） | クラウドTTSが継続課金（運営に継続コストが発生）なので、収益も継続型が整合。価値が「練習し続けること」にあり、定期利用ユーザーと相性が良い。 |
| 無料の核 | 端末内蔵TTS・台本3本まで・広告あり | 完全オンデバイスで原価ゼロ。学習されない保証もそのまま。アプリの価値を体験させてからの転換。 |
| 有料の核 | 高品質クラウド音声・台本無制限・ハンズフリー・広告なし・複数声モデル | いずれも「明確に上位の体験」かつクラウド音声は実コストを伴うため課金の正当性が高い。 |
| 価格 | 月額 **¥600**／年額 **¥4,800**（実質 月¥400、33%off）。買い切りLite **¥1,500** も併売検討 | 後述のコスト試算で1ユーザー月数十円〜の原価。ストア手数料15〜30%を引いても十分黒字。 |
| バックエンド | **RevenueCat（エンタイトルメント管理）+ 軽量TTSプロキシ**の二点のみ | レシート検証の自前実装を避けつつ、クラウドTTSのAPIキー秘匿とキャッシュ配布のため最小限のサーバは必要。 |
| プライバシー | **非学習・オンデバイス既定を維持。クラウド音声は明示的オプトイン** | 課金しても既定はオフライン。クラウドTTSへ送るのは「相手役のセリフ本文」のみ・学習非利用API・ZDR。 |

## 1. 収益化モデルの比較と主モデルの選定

### 1-1. 選択肢の比較

| モデル | 概要 | 長所 | 短所 | 本アプリ適性 |
|---|---|---|---|---|
| **無料＋サブスク（月/年）** | 基本無料、上位機能を定期課金で解放 | 継続収益でクラウドTTSの継続原価を吸収できる。LTVが高い。 | 解約される。継続価値の提示が必須。 | ◎ |
| **フリーミアム（機能ゲート）** | 無料で使えるが一部機能をロック。課金は買い切り or サブスク | 体験→転換の導線が自然。 | 「ゲートの線引き」設計が肝。 | ◎（サブスクと併用が前提） |
| **買い切り（1回課金）** | 一度払えば永久に有料機能 | 心理的ハードルが低い層に刺さる。サブスク疲れ層を拾える。 | クラウドTTSの継続原価を1回の支払いで賄えない（赤字リスク）。 | △（クラウドを含めない範囲なら可） |
| **従量クレジット（クラウドTTS用）** | 合成文字数に応じてクレジット消費・購入 | 原価と課金が直結し赤字化しない。重課金者から多く回収。 | UXが複雑（残高・補充）。「キャッシュ前提」だと消費が読みにくく不安にさせる。 | ○（サブスクの補助・上限超過分のみ） |
| **広告** | バナー/リワード広告 | 無料層からも薄く回収。 | 単価が低い（日本のニッチ実用アプリは特に）。練習中の没入を阻害。CSP/プライバシー面の追加考慮。 | ○（無料層の補助のみ。練習画面には出さない） |

### 1-2. 主モデルの推奨：フリーミアム + サブスク（クラウドTTSをゲート）

**根拠：**

1. **原価構造との整合。** 有料の主機能であるクラウドTTSは「使い続ける限り（少しずつでも）コストが発生」する継続原価である。買い切り単独だと、1回の支払いで永続的にクラウド合成を提供することになり、ヘビーユーザーで赤字化しうる。継続課金なら継続原価を継続収益で吸収でき、ユニットエコノミクスが安定する。

2. **ユーザーの利用形態。** 想定ユーザー（個人の俳優・声優志望・学生・オーディション受験者）は、**オーディション前の集中期間に毎日使い、終わると間が空く**という波がある。サブスクは「必要な月だけ入って解約」が可能で、年額より月額の心理的ハードルが低い。月額・年額の両建てで、波のある層は月額、習慣化した層は年額（割安）に誘導できる。

3. **無料層の価値が原価ゼロ。** 端末内蔵TTSによるMVPは完全オンデバイスで合成原価が一切かからない（`docs/01` 1-1）。つまり**無料層を厚く提供しても限界費用がほぼゼロ**で、トライアル兼マーケティングとして成立する。フリーミアムの「無料を太く」戦略を低リスクで採れる。

4. **「キャッシュ前提」が従量課金と相性が悪い。** `docs/01` 1-3 の通り、合成は台本ごとに1回でその後の再生は無料。つまり**ユーザーから見た消費量が直感的でなく**、従量クレジットだと「残高がいつ減るのか分からない」不安を与える。サブスクの「無制限・気にせず使える」体験のほうがこのキャッシュ設計と噛み合う。

5. **広告は補助に留める。** 日本語のニッチな実用アプリで広告のみに依存するとARPUが低すぎる。無料層の薄い回収＋有料転換のフックとして使い、**練習（リハーサル）画面には広告を出さない**（没入を守る）。

> 結論：**フリーミアム（機能ゲート）を土台に、解放手段を月額/年額サブスクとする**。買い切りLite（クラウド非依存の範囲）と広告（無料層のみ）は補助。従量クレジットはサブスク上限を超える極端なヘビーユースの「追い課金」としてのみ将来検討。

## 2. 無料／有料の線引き（機能ゲート設計）

「無料でアプリの core loop（取り込み→役選択→相手役読み上げ→練習）を完全に体験できる」ことを保証したうえで、**上位の音質・量・利便・非広告**を有料にする。core 機能そのものを人質に取らないのが転換と評判の両立の鍵。

| 機能 | 無料（Free） | 有料（Premium） |
|---|---|---|
| 台本の取り込み・解析・修正 | ✅（オンデバイス、制限なし） | ✅ |
| 保存できる台本数 | **3本まで** | **無制限** |
| 相手役の読み上げ | ✅ 端末内蔵TTS | ✅ 端末内蔵 + **高品質クラウド音声** |
| 声モデルの種類 | 性別×速度（内蔵ボイス） | **複数のクラウド声モデル**（自然・感情表現・役ごとに別声） |
| ト書きON/OFF・速度・ピッチ | ✅ | ✅ |
| ハンズフリー自動進行（音声認識） | ✕（または短時間お試し） | ✅ |
| 暗記モード・自己テープ録画（将来機能） | 一部 | ✅ フル |
| 広告 | あり（ホーム/詳細のバナー、取り込み完了後など。**練習画面には出さない**） | **なし** |
| エクスポート/共有（将来） | ✕ | ✅ |

**設計上の注意：**
- **無料の「3本まで」は寛容に。** オーディション1件は複数シーンを含むことがある。少なすぎると core を体験する前に壁に当たる。3本（または「同時保存3本、古いものを消せば追加可」）程度を初期値にしてA/Bで調整。
- **クラウド音声はオプトイン（後述 §5）。** 有料でも既定はオンデバイス、ユーザーが明示的に「高品質音声を使う」を選んだときだけクラウド合成。
- **ダウングレード時の挙動を定義。** 解約後に台本4本目以降を「閲覧・練習はできるが新規追加はできない」読み取り専用にする（データは消さない）。クラウド合成済みキャッシュは再生可能のまま残す。

## 3. コスト構造と価格設定

### 3-1. 前提（`docs/01-tech-research.md` 1-3「キャッシュ前提」より引用）

- セリフ練習は同じ台本を反復再生するため、**合成は台本ごとに1回だけ行いMP3をキャッシュ**し、以後の再生は無料。
- 1台本（相手役セリフ ≒ 3,000文字）あたりの**一回限り**合成コスト（`docs/01` の試算を引用）：

| サービス/モデル | 1台本(3,000字)あたり |
|---|---|
| Google Standard / WaveNet | 約 $0.012 |
| Google Neural2 / Polly Neural / Azure | 約 $0.045〜0.05 |
| OpenAI tts-1 / gpt-4o-mini-tts | 約 $0.045 |
| Google Chirp3 HD | 約 $0.09 |
| ElevenLabs Flash v2.5 | 約 $0.27 |
| ElevenLabs Multilingual v2 | 約 $0.54 |

### 3-2. 1ユーザーあたりのクラウドTTS原価 概算

想定：標準モデルを **Google Chirp3 HD（高品質・$0.09/台本）** に置く。声設定の変更・再解析で「再合成」が一定割合発生すると仮定し、**有効合成回数 = 台本数 × 1.5回**で見積もる（修正・声替えのやり直し分）。

| 月間の合成台本数（実質） | 有効合成回数 | Chirp3 HD原価/月 | ElevenLabs Flash原価/月（参考） |
|---|---|---|---|
| ライト（3台本） | 4.5 | 約 $0.41（≒¥62） | 約 $1.2（≒¥185） |
| 標準（8台本） | 12 | 約 $1.08（≒¥162） | 約 $3.2（≒¥495） |
| ヘビー（20台本） | 30 | 約 $2.70（≒¥405） | 約 $8.1（≒¥1,250） |

> 為替は概算 $1≒¥150 で換算。Googleの恒久無料枠（Chirp3 HD：1M字/月）は全ユーザー合算で消費するため、初期のユーザー数が少ないうちは**実質さらに安い／ゼロ**になりうる。

**含意：**
- 標準モデルにGoogle Chirp3 HDを採用すれば、**ほとんどのユーザーで月原価 ¥60〜¥200 程度**。ヘビーでも¥400前後。
- ElevenLabsは音質最上位だが原価が3〜4倍。**ElevenLabsはさらに上位の「プレミアム声プラン」または上位サブスク限定**にして原価を分離するのが安全。
- キャッシュにより**再生回数が増えても原価は増えない**のが本アプリ最大の強み。原価は「合成（＝台本登録・声替え）回数」にのみ比例する。

### 3-3. 価格設定（日本円・持続可能性）

| プラン | 価格 | ストア手数料控除後（概算） | 月あたり原価 | 粗利の目安 |
|---|---|---|---|---|
| **月額** | **¥600 / 月** | 〜2年目以降サブスクは15%手数料 → 約¥510（初年30% → 約¥420） | ¥60〜¥400 | 高（標準ユーザーで¥350前後/月） |
| **年額** | **¥4,800 / 年**（実質 月¥400, 33%off） | 15%控除後 約¥4,080/年（≒月¥340） | 同上 | 中〜高（前払いでチャーン低減） |
| **買い切りLite** | **¥1,500（一括）** | 30%控除後 約¥1,050 | **クラウド非依存機能のみ**（台本無制限・広告なし・複数の内蔵ボイス・ハンズフリー）。クラウド音声は含めない | 高（継続原価ゼロ） |
| **追いクレジット**（将来・任意） | 例 ¥480 / 100台本ぶん合成 | 30%控除後 約¥336 | 約¥0.9/台本（Chirp3 HD） | サブスク上限超過分の保険 |

**設計根拠：**
- **月¥600 は「コーヒー1杯ぶん」のアンカー。** 日本のサブスクアプリの実用カテゴリで受け入れられやすい帯。原価 ¥60〜¥400 に対し、初年30%手数料を引いても標準ユーザーで黒字、2年目以降（15%）はさらに余裕。
- **年額は月額の8ヶ月ぶん（33%off）。** 前払いでチャーンを抑え、年間を通したクラウド原価のならしにも効く。
- **買い切りLiteは「サブスク忌避層」の受け皿。** ただし**継続原価を発生させるクラウド音声を含めない**ことで、1回課金でも赤字化しない設計にする。クラウド音声が欲しければサブスクへ、という自然な分岐。
- **ヘビーユーザー対策：** サブスクに「月あたり合成台本数のソフト上限（例：月50台本＝原価約¥700ぶん）」を設け、超過時は追いクレジット購入か内蔵TTSにフォールバック。乱用（業務的な大量合成）で原価が価格を超えるのを防ぐ。
- **無料トライアル：** 年額に7日間の無料トライアルを付与（App Store / Google Play の introductory offer）。core を内蔵TTSで体験済みのユーザーに、クラウド音質を試させて転換。

### 3-4. 損益分岐の感覚

標準ユーザー（月原価 ≒¥160）で考えると、月額¥600・初年手数料30%控除後 ≒¥420 の手取りから原価¥160 を引いて**約¥260/ユーザー/月の貢献利益**。固定費（後述のサーバ/RevenueCat）を賄うのに必要な有料ユーザー数はごく小規模で済む（§4-4 参照）。

## 4. 実装要件（ストア課金・検証・手数料・税）

### 4-1. プラットフォームの規約・課金基盤

- **デジタル機能（クラウド音声・台本無制限など）はアプリ内課金（IAP）必須。** Apple App Store / Google Play とも、アプリ内で消費されるデジタルコンテンツ/機能は外部決済ではなくストアのIAPを使う規約。サブスクは Auto-Renewable Subscription として登録する。
- **StoreKit 2（iOS 15+）** … トランザクションとエンタイトルメントをOSが管理。`Transaction.currentEntitlements` で現在の権利を取得でき、レシート手動検証の必要性が大きく下がる。
- **Google Play Billing Library（v6+）** … サブスクは「base plan + offers」モデル。`queryPurchasesAsync` で有効購入を取得。
- **Flutter からの接続手段は2択（§4-2）。**

### 4-2. `in_app_purchase` vs RevenueCat

| 観点 | `in_app_purchase`（公式パッケージ） | **RevenueCat（`purchases_flutter`）** |
|---|---|---|
| 役割 | StoreKit / Play Billing の薄いラッパー | 課金SaaS。両OSのエンタイトルメントを一元管理 |
| エンタイトルメント管理 | **自前実装が必要**（購入状態の保持・復元・期限判定） | **SaaSが管理**。`CustomerInfo.entitlements.active` を見るだけ |
| レシート/購入検証 | 自前 or バックエンドで実装 | **RevenueCatサーバが検証**（バックエンドレスでも可） |
| 解約・更新・返金の追跡 | 自前でストアの状態同期 | Webhook/ダッシュボードで一元把握、分析も付随 |
| 価格 | 無料 | 一定の月間売上（執筆時点で月 $2.5K MTR 相当）まで無料、超過で従量（一般に売上の約1%） |
| バックエンド要否 | サーバを立てるなら検証を自前実装 | **専用バックエンド不要**でエンタイトルメントが成立 |

**推奨：RevenueCat。**
- 本アプリは**バックエンドレス指向**（`docs/02` の通り台本はオンデバイス）。自前のレシート検証サーバを立てたくない。
- RevenueCatは**サーバ側でレシート検証とエンタイトルメント管理を肩代わり**し、Flutterからは「いまPremiumか？」を1行で判定できる。クロスプラットフォームの購入復元も容易。
- コストは小〜中規模なら無料枠内。売上が立ってからの従量（約1%）は、自前で検証サーバを運用・保守する人件費より安い。

### 4-3. レシート検証とバックエンドの要否（重要な論点）

本アプリはMVPがバックエンドレス。だが収益化フェーズで**2つの理由から軽量サーバ（または対応SaaS）が要る**：

1. **エンタイトルメント検証** … 「この端末は本当に課金済みか」を信頼できる形で判定する必要がある。クライアントだけの判定は改ざんに弱い。
   → **RevenueCatで充足**（専用サーバ不要）。RevenueCatがストアと検証・同期する。

2. **クラウドTTSのAPIキー秘匿とコスト制御** … クラウドTTS（Google/ElevenLabs等）のAPIキーを**アプリに埋め込むと漏洩・乱用される**（誰でも合成し放題＝原価爆発）。よって：
   - **軽量TTSプロキシ（サーバレス関数で可）を立てる。** クライアント → プロキシ → クラウドTTS。プロキシ側でAPIキーを保持。
   - プロキシは呼び出し前に**エンタイトルメントを確認**（RevenueCatのサーバAPI/Webhookで「課金中ユーザーか」を検証）し、**レート制限**（§3-3のソフト上限）を課す。
   - 合成結果（MP3）をキャッシュに格納し配布。台本本文は**保存せず通過のみ**（プライバシー §5）。

> まとめ：**「エンタイトルメント＝RevenueCat」「クラウドTTSの鍵秘匿とレート制限＝最小のサーバレスプロキシ」**の二点だけバックエンドを持つ。台本の保管・解析は引き続きオンデバイスのまま。MVP（無料・内蔵TTSのみ）の間はこのサーバすら不要で、Premium導入時に追加する。

### 4-4. ストア手数料

- **Apple / Google とも標準 30%、サブスクは継続2年目以降（同一ユーザーが12ヶ月継続後）15%。** Appleの Small Business Program（年間売上 $1M 未満）に登録すれば**初年から15%**。Google Play も「年間最初の $1M は15%」。
  → 小規模アプリの本案は**実質おおむね15%手数料で計画**してよい（§3-3の手取りは保守的に初年30%でも黒字になるよう設定済み）。
- 固定費の損益分岐（概算）：月の固定費を RevenueCat無料枠 + サーバレスプロキシ ≒ ¥0〜数千円とすると、**月額¥600の有料ユーザーが数十人**で固定費を超え、以降はほぼ貢献利益がそのまま積み上がる。

### 4-5. 消費税・インボイス

- **ストア経由のIAPは、ストア（Apple/Google）が表示価格に消費税を含めて徴収**し、開発者にはネット額が支払われる構造が基本（日本のApp Store価格は税込表示）。表示価格 ¥600 は**税込のユーザー支払額**として設計する。
- 開発者側の申告：国内売上は消費税の課税対象になりうる。**インボイス制度**下では、課税事業者か免税事業者かで扱いが変わる。一定規模を超えたら課税事業者登録・適格請求書対応が必要になるため、**税理士に確認**（本書は法務・税務助言ではない）。
- 価格は**ストアの価格帯（Tier/価格ポイント）に合わせる**。為替変動でクラウド原価（USD建て）が上振れしても粗利が確保できるよう、原価の2〜3倍以上のマージンを保つ（§3で確保済み）。

## 5. プライバシー整合（非学習・オンデバイス既定の維持）

収益化は**`docs/02` §3-8 の非学習ポリシーを一切緩めない**ことを大前提とする。

- **既定は完全オンデバイス。** 無料・有料を問わず、初期状態は内蔵TTS（クラウド送信ゼロ＝学習経路が原理的に存在しない）。課金しても自動でクラウドに切り替わらない。
- **クラウド音声は明示的オプトイン。** 有料ユーザーが「高品質音声を使う」を選んだ初回に、`docs/02` の同意ダイアログ（どのデータが・どこへ・学習に使われないか）を提示。OFFが既定。
- **送信は最小限。** クラウドTTSへ送るのは**合成対象＝相手役のセリフ本文のみ**。自分の役・ト書き（OFF時）・メタ情報は送らない。任意で固有名詞マスキング（`docs/02` §3-8-5）。
- **学習非利用が保証された提供元のみ・ZDR。** Google Cloud TTS（契約上、顧客データを基盤モデル学習に不使用）を標準採用。ElevenLabs等を足す場合も同等のエンタープライズ規約・Zero Data Retention を確認。
- **TTSプロキシは台本を保存しない。** プロキシは合成のため本文を通過させるが永続保存しない。MP3キャッシュは**端末側**に持つ（サーバ保管しない）か、保管する場合は暗号化＋ユーザー削除導線（`docs/01` 2-3）。
- **広告のプライバシー配慮：** 広告SDKを入れる場合、ATT（iOSのトラッキング許可）対応・非パーソナライズ広告の選択肢を用意。練習画面（台本本文が映る画面）には広告SDKを初期化・表示しない。台本テキストは広告ネットワークに渡さない。
- **ストア表記との整合：** App Store の「プライバシーラベル」/ Google Play の「データ セーフティ」に、**「台本データを収集・学習利用しない」「クラウド音声利用時のみセリフ本文を音声合成のため送信（保存しない）」**を正確に記載。プライバシーポリシーにも明記。

> 原則：**課金してもプライバシー水準は下がらない。クラウドは“速くて自然な相手役”というオプションであって、データ取り扱いのトレードオフではない。**

## 6. 段階的ロールアウト案

| フェーズ | 内容 | 課金 | バックエンド | 目的 |
|---|---|---|---|---|
| **0. MVP（現状）** | 完全オンデバイス・内蔵TTS・台本制限なし | なし | なし | core loop の検証・初期ユーザー獲得・レビュー収集 |
| **1. フリーミアム土台** | 台本3本まで・広告（ホーム/詳細のみ）を導入。**買い切りLite ¥1,500**（台本無制限・広告なし・ハンズフリー・内蔵の複数ボイス）を販売 | **IAP（買い切り）** | **RevenueCatのみ**（エンタイトルメント） | 課金導線の検証。クラウドなしで黒字の土台を作る。原価リスクゼロ |
| **2. サブスク + クラウドTTS** | 月額¥600/年額¥4,800を追加。**Google Chirp3 HD** を標準クラウド音声に。オプトイン同意UI・ソフト上限・キャッシュ | **IAP（サブスク）** | RevenueCat + **TTSプロキシ（サーバレス）** | 継続収益化の本命。継続原価を継続収益で吸収 |
| **3. プレミアム声・高度機能** | ElevenLabs等の最上位音声を上位プラン/追い課金に。役ごとの別声プロファイル。暗記モード・自己テープ録画のフル解放 | サブスク上位 + 追いクレジット | 同上（レート制限強化） | ARPU向上。ヘビーユーザーの収益化と原価分離 |
| **4. 最適化** | 価格・無料台本数・トライアル長のA/B、年額誘導、解約理由分析（RevenueCat） | 同上 | 同上 | LTV/チャーン最適化 |

**ロールアウト指針：**
- **各フェーズで原価が収益を超えない構造を維持**（フェーズ1はクラウドなし＝原価ゼロ、フェーズ2以降はソフト上限とプロキシのレート制限で防御）。
- **既存無料ユーザーを尊重。** フェーズ1で台本制限を入れる際、**それ以前に保存済みの台本は制限対象外（グランドファーザリング）**にして反感を避ける。
- **クラウドは常にオプトイン。** どのフェーズでも「課金＝勝手にクラウド送信」にはしない（§5）。
